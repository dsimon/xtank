## Goal

Give the display-free server an explicit human binding — name → controller
(session id) → combatant/vehicle slot — for one human plus one drone, with
human flags and init/death/respawn semantics preserved and **zero `Terminal`
objects**. Legacy terminal-facing setup is isolated behind a single safe
accessor so the X front-end is untouched.

`server_player_terminal(player_index)` returns `terminal[player_index]` when the
legacy terminal exists and `NULL` otherwise. With terminals present the engine
sees the *identical* terminal it always did; with none every legacy
terminal-facing step is simply skipped. No fake `Terminal`, no human-as-bot:
`Combatant.num_players == 1` and `Vehicle.teleport == TRUE` are preserved for
the human, `num_players == 0`/`teleport == FALSE` for the drone.

### The §1 gaps, closed deliberately

1. `ServerPlayers` still maps names to terminal slots for the X path; the new
   `ServerHumanBinding` maps *controller → slot* with a generation, and is the
   only identity a terminal-free human has. `init_combatants()`/`setup_combatant()`
   and `activate_vehicle()`/`inactivate_vehicle()` no longer dereference
   `terminal[]` for a player without a terminal.
2. `activate_vehicle()` still distinguishes humans through
   `Combatant.num_players` (that is the rule); it now takes the terminal branch
   only when a terminal actually exists.
3. Rebinding a slot bumps the displaced binding's generation and unbinds it, so
   a stale controller cannot drive a respawned/reassigned slot
   (`server_players_validate()` rejects a stale generation or wrong slot).
