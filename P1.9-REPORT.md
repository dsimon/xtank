## Loop design (`Src/server_loop.c`, new)

- **Fixed step.** The loop calls exactly one `server_step()` per tick,
  independent of rendering or of how long the work took.
- **Absolute monotonic deadlines.** After a match reset the loop records
  `t0 = CLOCK_MONOTONIC`. The deadline for tick `N` is
  `t0 + N * 1e9 / tick_hz` nanoseconds, evaluated in integer arithmetic. The
  15 Hz period (`66666666.66… ns`) is never rounded per tick, so the schedule
  accumulates the exact rational `1/15 s` and cannot drift.
- **Catch up without skipping.** `server_loop_pace(N)` sleeps with
  `clock_nanosleep(CLOCK_MONOTONIC, TIMER_ABSTIME, deadline)`; if the deadline
  has already passed it returns immediately. A slow tick therefore runs the
  next ticks back to back until the schedule is met — no tick is ever skipped.
- **Fast replay bypasses sleep only.** `XTANK_SERVER_FAST=1` (or the legacy
  `-D`/`NoDelay`) makes `server_loop_pace()` return without sleeping; the
  simulation path and every `server_step()` are identical. `timing.sh` proves
  the two dumps are byte-identical.
- **Bounded work reporting.** Per-tick wall time is recorded in a fixed
  1 µs-resolution histogram (capped at 100 ms). The loop prints one line:
  `SERVER-LOOP hz=… ticks=… fast=… avg_us=… p99_us=… max_us=… overruns=…
  late=…` to stderr and, if set, to `XTANK_LOOP_REPORT`; `overruns` counts
  ticks over the frame budget and `late` counts deadlines already missed on
  entry.
- **Test bound.** `XTANK_SERVER_TICKS=N` stops after `N` ticks and reports, so
  a finite deterministic dump can be compared between paced and fast runs.
- **Configuration.** `server_init()` reads `XTANK_TICK_HZ` into
  `ServerConfig.tick_hz`; the display-free (`NULL_BACKEND`) server defaults to
  `SERVER_DEFAULT_TICK_HZ` (15). The X front-end leaves `tick_hz == 0`, so
  `server_loop_active()` is false and its legacy pacer is untouched.

## Legacy pacer removed from the server path

- `Src/actions.c` — `check_game_speed()` and `set_game_speed()` return early
  when `server_loop_active()`, so the server path never waits on or arms the
  signal pacer.
- `Src/icounter.c` — `start_real_counter()` and `wait_for_real_counter()` are
  no-ops when `server_loop_active()`, so no `ITIMER_REAL`/`SIGALRM` frame timer
  is installed and `pause()` is never used for pacing on the server path.
  (`SIGVTALRM` from the cooperative threader is unrelated and unchanged.)
- `Src/server_core.c` — `server_tick_pace()` is wired to the monotonic pacer
  when active, otherwise to the legacy `check_game_speed()`.
- `Src/setup.c` — `play_game()`'s inner `do { server_step(); } while (…)`
  became `status = server_loop_run();`.

Runtime audit (`strace -f -e trace=rt_sigaction,pause,setitimer,alarm` on a
3-tick paced server run): **0 `SIGALRM` handlers, 0 `pause()`, 0
`ITIMER_REAL`**; the only timers are `ITIMER_VIRTUAL` for the threader. The
same audit is part of `timing.sh` when `strace` is present.

## Production intent consumption (P1.7 deferral)

`Src/animate.c` now consumes the bounded queue at the exact legacy input seam
(after `run_all_programs()`, before terminal input/movement):

```c
#ifdef STATE_DUMP
	if (xtank_replay_run)
		xtank_replay_run(frame);        /* oracle adapter (P1.7) */
#else
	(void) server_consume_intents(frame); /* production server (P1.9) */
#endif
```

The oracle build keeps its P1.7 adapter; the production server build calls
`server_consume_intents()` directly. `server_consume_intents` is declared
locally so the frozen reference (always built `-DSTATE_DUMP`, without
`server_core.c`) never depends on it. The non-oracle `xtank-headless` object
references the symbol (`nm Src/nobj/animate.o` → `U server_consume_intents`).
