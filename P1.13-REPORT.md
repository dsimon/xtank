## Scheduling design

### Mode selection (`Src/Threads/threadglue.c`)

`init_threader()` calls `program_set_cooperative(server_loop_active())` after
`thread_setup()`. The monotonic server loop owns pacing for the null/server
build (`server_loop_active()` is true because `server_init()` sets
`tick_hz = SERVER_DEFAULT_TICK_HZ`), so the server selects cooperative
scheduling. The X front-end leaves `tick_hz == 0`, so it keeps the legacy
CPU-time scheduler unchanged. No new file or server-core hook is needed.

### One iteration/yield per eligible tick (`Src/program.c`)

`run_all_programs()` is unchanged: it walks `live_vehicles[0..num_veh_alive)`
and each vehicle's programs in stable legacy order, and keeps the exact legacy
eligibility gate `prog->total_time <= frame * PROGRAM_ALLOT`. That gate plus
`init_programs()` still setting `total_time = (frame + 1) * PROGRAM_ALLOT`
preserves the first-tick and respawn deferral precisely.

In cooperative mode `run_program()`:

- arms the yield watchdog, `thread_switch()`es into the program, and disarms on
  return — i.e. it runs the program until its next `done()`;
- charges **exactly** `PROGRAM_ALLOT` to `prog->total_time` instead of reading
  the virtual timer.

Because a drone iteration is far below the 10 ms virtual-timer tick, the legacy
path already charged exactly `PROGRAM_ALLOT` (elapsed 0, `stop_program()`
clamps to 5000), so the arithmetic — and therefore every scheduling decision
and every frozen dump byte — is identical.

`check_time()` returns immediately in cooperative mode (no CPU-budget
preemption), and `stop_program()`/`done()` just yields to `scheduler_thread`
with no clock accounting. `Src/Threads/thread.c` and the swapcontext path are
untouched.

### Yield watchdog (`Src/icounter.c`)

Around each cooperative `run_program()` the existing `ITIMER_VIRTUAL` timer is
armed with `elapsed_time = 0` (`program_watchdog_start`) and disarmed on yield
(`program_watchdog_stop`). If a program does not yield before the budget
(default 1 s of CPU, `XTANK_BOT_WATCHDOG_MS` override), the SIGVTALRM handler
prints `XTANK WATCHDOG: bot '<name>' (vehicle N) did not yield ...` and
`_exit(70)`. It never preempts the program or silently yields it, so a
well-behaved run is unaffected. This is failure diagnosis, not scheduling; no
CPU-time value influences who runs.

## `Tests/phase1/bots.sh` (new)

`--repeats N [--cpu-load]` builds the null candidate and replays every frozen
drone scenario N times, optionally with a pool of busy-loop CPU hogs running.
Every repeat must complete and be byte-identical to the frozen SHA-256 and to
the other repeats. It also runs:

- **Yield audit** (strace): over a bounded 50-tick combat-2drone run the
  number of `setitimer(ITIMER_VIRTUAL)` calls must be exactly
  `2 * ticks * bots` — one arm + one disarm per eligible bot run, i.e. exactly
  one iteration/yield per eligible tick.
- **Watchdog diagnosis**: a self-contained fixture over the real `icounter.c`
  runs a bot that never yields and requires exit code 70 plus the diagnostic
  line, proving failure is diagnosed rather than masked.

`--minutes M --vehicles 4 --resets R` runs the 4-drone match through R
lifecycle resets in one process with fast replay. It requires the simulated
duration to reach M minutes, all `R+1` epochs, clean resets
(`SERVER-LIFECYCLE ... cv=null term=null`), and, from the v2 dump, movement
(per-vehicle displacement), targeting (distinct turret angles) and fire
(bullets spawned).

## Deferred / notes

- The cooperative mode retains the Linux `swapcontext` threader; no fibers work
  was done, as specified.
- The watchdog uses `ITIMER_VIRTUAL` (CPU time), so host load cannot cause a
  false positive and the P1.9 strace audit (no SIGALRM / no `ITIMER_REAL` /
  no `pause()`) is unaffected. It can be disabled per-run with a non-positive
  `XTANK_BOT_WATCHDOG_MS`; the default is 1 s.
- The 60-minute soak dumps v2 at period 1 (v2 ignores `XTANK_DUMP_PERIOD`), so
  its dump is large; it lives on the overlay filesystem, not in the checkout.
- `timing.sh` was run against the source immediately before a buffer-clamp
  cosmetic change to the (never-executed-in-normal-runs) watchdog diagnostic;
  it is behaviorally inert and the full G and bots acceptance were re-run
  against the final source.
