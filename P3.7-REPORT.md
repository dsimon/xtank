## 3. Implementation

### 3.1 The single departure path (all reasons)

`server_session_depart(s, reason)` is the only RUNNING-path removal. It runs at
a tick boundary and is idempotent (`server_session_destroy` clears `used`):

1. marks the peer `disconnected` (so it leaves the roster, the result
   recipients and the remaining-human count) and records the reason;
2. while the match is Running and the peer owns a slot, executes the P3.2
   contract — `intent_cancel_player(slot)`, `server_depart_vehicle(slot)`,
   `server_players_unbind_slot(slot)`;
3. if no admitted human remains, finalizes the match (`GAME_OVER`, abort/
   no-winner) through `server_session_finish()` and returns to the lobby via
   `server_session_return_to_lobby()`;
4. releases the peer record (transport/net session, binding generation and
   administrator transfer happen in `server_session_destroy`).

Call sites: `XTK_MSG_QUIT` (voluntary, reason 0); `transport_poll_disconnect`
(reason `XTK_ERR_TIMEOUT`); the `server_session_step` timeout clause
(`XTK_ERR_TIMEOUT`); the bounded reliable-backlog check in
`server_session_service` (`XTK_ERR_QUEUE_SATURATED`); and the service reclaim
loop for peers already marked disconnected.

### 3.2 Removal with no kill/score/death/RNG/explosion

`server_depart_vehicle(slot)` calls only `inactivate_vehicle()` (which clears
`VS_is_alive`, kills program threads, detaches any terminal and clears the map
occupancy flag) and swap-with-last removes the vehicle from `live_vehicles[]`
and, when respawn-waiting, `dead_vehicles[]`. It never calls
`kill_vehicle`/`explode_vehicle`/`unmake_vehicle`, and it never touches
`teamdata[]`, `num_teams`, scores, kills, deaths or any rule formula.

### 3.3 Player-scoped input cancel

`intent_cancel_player(player)` drops only that controller's queued intents and
clears only that controller's held controls. The P3.2 audit showed the only
prior cancel, `intent_reset()`, also wiped the survivor; the new seam leaves the
survivor's input intact, so no ghost projectile is fired by a removed tank.

### 3.4 Retained records and reference-derived cleanup

A departed vehicle's `actual_vehicles[]`/`combatant[]` storage, name, earned
score/kills/deaths, weapon arrays and special records stay allocated until the
normal reset, so every in-flight `Bullet.owner` and disc/special reference
stays valid and follows unchanged projectile rules. `server_match_reset()`
reattaches each retained record to the dead list before `game_cleanup()`, which
frees its thread/stack/special storage exactly once. No `Src/setup.c` change is
needed. Results retain the departed combatant's score/name with
`XTK_FLAG_DEPARTED` set (applied to the `XtkResults` copy in
`server_session_finish`, leaving `server_events.c` untouched).

### 3.5 Admin transfer, lobby return and rejoin

`server_session_destroy` transfers administration to the first remaining
admitted human and emits the reliable `LOBBY_STATE` barrier, so the transfer is
reliable and unique. When the last human departs the world is emptied and the
server returns to the listening lobby. `server_session_accept` already rejects
any join while not in Lobby, so rejoin while Running fails; the next-lobby
rejoin is a fresh connection/controller identity (monotonic counters) with a
fresh binding generation, and old commands fail epoch/dedup/ownership
validation.

## 5. Fixture coverage — `departure.sh` (67 checks, 3 identical repeats)

- **Ordinary reference:** the frozen P3.2 two-human hash
  `5625b7035aae2e82` is reproduced, proving the removal seam leaves the ordinary
  simulation untouched.
- **Live QUIT departure:** one tick-boundary removal; departed tank leaves the
  live list and is not alive; survivor alive and still scored; no score/death/
  kill change for either human; no new explosion; team counts/`num_teams`
  unchanged; departed slot marked; retained record keeps the live projectile
  owner valid; survivor binding still validates while the departed controller
  no longer owns its slot; survivor is the unique administrator and receives a
  `LOBBY_STATE` with the new admin; running rejoin rejected; survivor progresses
  ~40 ticks with the departed tank never re-entering either list; a natural win
  yields marked departing result records (retained name/score,
  `XTK_FLAG_DEPARTED`) and an unmarked survivor record; reset releases the
  retained records (`server_departed_count()==0`) and empties the world.
- **Respawn-waiting departure:** a killed, dead-list-waiting tank leaves the
  dead list, its record is retained, and it never returns over 120 ticks.
- **Pending/held input:** both controllers hold fire; the departure cancels only
  the departing controller's held fire, preserves the survivor's, and fires no
  ghost projectile from the removed tank.
- **Timeout:** a silent peer is removed strictly after 2,000 ms (the P3.6
  boundary is re-verified by `admission.sh`), with no score/kill, retained
  record, invalidated controller and a surviving human still Running.
- **Saturation / disconnect / idempotence:** saturated and disconnected peers
  use the same path; a repeated departure is a no-op.
- **No humans:** simultaneous QUITs empty the world, release all retained
  records and return to the listening lobby at two-human capacity.
- **Rejoin:** a fresh join gets new connection/controller ids; the old
  controller cannot claim the fresh tank; a fresh two-human start builds a clean
  world; no stale departed markers.
- **Cycles:** five disconnect/rejoin cycles on one running server stay clean
  with fresh identities each epoch.
