## v2 format specification

Emitted once per tick (`XTANK_DUMP_PERIOD`, default 1 for v2) and at every
`animate()` exit, including early `GAME_OVER`/`GAME_QUIT` returns before
`game_rules`. ASCII, line-oriented, one logical record per line, no pointers,
no padding and no screen coordinates (the `Loc.screen_x/screen_y` arrays are
never read). Records:

```
F2 <tick> epoch <e> status <gamerules-retval> alive <a> dead <d> nb <bullets> ne <explosions> nv <vehicles>
V  <num> team <t> status <hex> grid <gx> <gy> box <bx> <by> pos <x> <y> z <z>
   heading <f> oldheading <f> desired <f> drive <f> speed <f> xspeed <f> yspeed <f>
   rot <r> oldrot <r> fuel <f> heat <h> armor <6 sides> discs <n> deathtimer <d>
   nweapons <nw> nturrets <nt> score <s> kills <k> deaths <d>
VW <num> <idx> type <t> status <hex> ammo <a> reload <r> hits <h>
VT <num> <idx> angle <f> desired <f> flag <d>
VC <num> timetocamo <d> camod <d> oldcamod <d> rcs <f> stealthy <f> normal <f>
B  <idx> owner <o> type <t> life <l> thrower <th> safety <s> hurt <h>
   state <st> rot <r> grid <gx> <gy> box <bx> <by> pos <x> <y> z <z> xspeed <f> yspeed <f>
E  <idx> x <x> y <y> z <z> life <l> color <c>
MX <gx> <gy> flags <hex> type <t> team <tm> code <c> strength <s>       # maze mutations
MPH <num> need_redisplay <b> map_invalid <b> num_symbols <n> num_landmarks <n>
MP <num> <gx> <gy> flags <hex> type <t> team <tm> strength <s>          # mapper exploration delta
ML <num> <x> <y> type <t> team <tm>                                     # mapper landmarks
RNH <num> num_blips <n> pos <p> start <sx> <sy> end <ex> <ey>
RB <num> <idx> x <x> y <y> life <l> view <v> oldview <ov> flags <f>     # radar records
NRH <num> frame_updated <f> need_redisplay <b>
NRB <num> <idx> draw <x> <y> <radar> <tactical> <friend>                # new-radar records
```

`MX`/`MP` emit only boxes whose persisted fields (`flags,type,team,strength`)
changed since the previous tick (all inside-maze / explored boxes on the first
tick). `epoch` increments whenever the per-process frame counter decreases,
i.e. at a reset epoch. `status` is the `game_rules()` return (`0` running,
`1` over, `3` reset).

## Bot-free replay

`reference_input.c` is compiled into both the frozen X reference and the
candidate oracle (the same source), so the reference independently calls the
legacy controls at the pre-terminal input seam and the candidate runs the
identical op stream. Trace ops: `drive`, `driveabs`, `turn`, `aimv` (aim at a
target's live position), `aim` (world coordinate), `fire`, `firehold`, `chase`,
`standoff`, `wep`. Persistent tracking and de-wedging are reset at `frame==1`,
so every epoch replays identically. `aimv`/`chase`/`standoff` resolve world
coordinates from live state (deterministic identical arithmetic in both
builds), matching the P1.7 "world-coordinate turret aim" contract.

Because the legacy Combat game ends the process at a reset (`-X` AutoExit, and
`display_game_stats` never restarts Combat), only one epoch per process is
reachable; `reset` is therefore asserted as the `GAME_RESET` (`status 3`)
tick, and the `epoch` field/late-exit handling is in the format and event
emitter ready for P1.6's lifecycle harness.

| win | ✓ tick 200 (2000) | — | ✓ tick 231 (1000) |
| reset (status 3) | ✓ tick 200 | — | ✓ tick 231 |

Union over the two Arena traces covers every event on Arena; `trace-quadrant`
covers every event on Quadrant in one trace. Arena needs two traces because
the legacy Combat reset path terminates after the winning kill (Winning 1000),
while reaching a second kill at Winning 2000 requires open-loop maze
navigation that the frozen trace does not guarantee after the respawn
(post-respawn separation stayed >1000 px — a maze-topology property of
`Arena.m`, not a simulation difference).

Event definitions (from the v2 dump only): **wall** = explosion count grew
while zero bullets were in flight; **tank** = minimum centre distance between
live vehicles < 110 px; **bullet** = armor decreased on a tick with bullets in
flight; **directional** = at least one of FRONT/BACK/LEFT/RIGHT decreased
during a bullet hit; **death** = `deaths` counter increased or `VS_is_alive`
cleared; **respawn** = `VS_is_alive` regained after a death; **score** =
`owner.score` increased; **win** = `score >= winning_score`; **reset** =
`game_rules()` returned `GAME_RESET`.
