## Intent schema (`Src/Include/intent.h`)

Each intent is tagged `(tick, player, sequence)` and carries an op plus two
doubles. One controller owns one tank (player index → `actual_vehicles[player]`).

| Op | Meaning | Kind |
| --- | --- | --- |
| `INTENT_DRIVE_REL` | relative drive in `[-9,9]` | one-shot |
| `INTENT_DRIVE_ABS` | absolute drive | one-shot |
| `INTENT_HEADING` | desired heading (radians) | one-shot |
| `INTENT_AIM_WORLD` | world-coordinate turret aim | one-shot |
| `INTENT_AIM_TARGET` | tracked target (`-1` releases) | held |
| `INTENT_FIRE` | fire all weapons once | one-shot |
| `INTENT_FIRE_HOLD` | hold (`a!=0`) / release fire | held |
| `INTENT_WEAPON` | weapon enable/disable/fire (`a=weapon`, `b=action`) | one-shot |
| `INTENT_CHASE` | chase target, `b=drive` (`-1` releases) | held |
| `INTENT_STANDOFF` | stand-off target, `b=distance` (`-1` releases) | held |

`AIM_TARGET`/`CHASE`/`STANDOFF` are the persistent controls the frozen bot-free
traces need; they mirror the reference's legacy operations (including its
anti-wedge arithmetic) so the candidate moves identically without sharing the
reference implementation.

## Queue semantics (`Src/intent.c`)

- **Bound:** `INTENT_QUEUE_MAX = 128`. A push that would exceed it returns
  `INTENT_REJECT_FULL` (bounded overflow) and changes nothing.
- **Ordering:** `intent_consume(tick)` applies held controls first (all tanks'
  aim, then chase, then stand-off), then this tick's queued intents in stable
  `(player, sequence)` order, then held fire in player order for live tanks.
  Intents with a later tick stay queued.
- **Rejection, no state effect:** `INTENT_REJECT_BADOP` (unknown op / bad
  arguments), `INTENT_REJECT_BADPLAYER` (no such controller/tank),
  `INTENT_REJECT_FOREIGN` (target is not a vehicle here),
  `INTENT_REJECT_STALE` (`tick` already consumed),
  `INTENT_REJECT_DUPLICATE` (same `(player, tick, sequence)` still pending),
  `INTENT_REJECT_FULL`.
- **Held controls:** held fire re-fires each tick until released; held target
  aim re-resolves each tick; all held state is cleared by `intent_reset()`,
  which `server_match_init()`, `server_match_reset()`, and `server_init()` call.
- **Consume seam:** `server_consume_intents(tick)` = `intent_consume(tick)`,
  defined in `Src/server_core.c`. The candidate's oracle adapter
  (`Src/intent.c`, `-DSTATE_DUMP`) loads `XTANK_TRACE` once, enqueues every
  command tagged with its tick at frame 1, and consumes the current tick at the
  pre-terminal input seam (after `run_all_programs()`, before movement). The
  production `server_step()`/loop will call the same seam (P1.9); the queue and
  reset wiring are already server-owned.

`Src/input.c` gains `input_event_intent()`, the legacy-event→intent adapter for
a future server input source; `anim_input()` itself is unchanged, so the X
front-end's gameplay is untouched. `Src/actions.c` gains the neutral application
primitives `action_aim_world()`/`action_fire_all()`; `Src/lowlib.c` gains the
bounds-checked `lowlib_actual_vehicle()` accessor.
