## Goal

complete per-player world, map/radar and own-HUD DTOs without any simulation
mutation. The exporter is called **after `server_step()` completes**, is strictly
read-only, and is the seam the network session (P2.8) will use to build
`VIEW_SNAPSHOT`s.

## The authorization table (derived in `docs/VIEW-v1.md`)

### Camera / viewport

The legacy `animate()` terminal pass places the animation window at the
controlled vehicle; the same window is the authorization rule. From
`Src/update.c:update_screen_locs()` and `Src/Include/{screen.h,tanklimits.h}`:

- `ANIM_WIN_WIDTH = ANIM_WIN_HEIGHT = 768`, `NUM_BOXES = 4` per side, so one box
  is `BOX_WIDTH = BOX_HEIGHT = 192` world units.
- The camera is centred on the controlled vehicle's `Loc` with a **half-extent
  of `ANIM_WIN_WIDTH / 2 = 384`** world units, half-open at the far edge.
- A point is in view iff `own.x - 384 <= x < own.x + 384` (same for y).

This is the legacy animation view rule — **not** an invented wall-occlusion or
line-of-sight rule. Walls do not hide vehicles. The observer/`full_*` views are
not exported.

### Field classes (protocol-v1 `PROTOCOL-v1.md` §5)

| Class | DTO | Source | Rule |
| --- | --- | --- | --- |
| `SELF` | `XtkSelfState` | own `Vehicle`/`Combatant` | generation, armor by side, fuel, heat, score, ammo, weapon-enabled bitmap and reload; clamped to `u16`. |
| `VISIBLE` | `XtkVehicleView` | live vehicles in the viewport | slot, generation, body kind, lifecycle flags, `x`/`y`, body/turret angle, body/turret picture. No private remote state. |
| `VISIBLE` | `XtkBulletView` | `Bset` entries in the viewport | array-index id, position, `atan2(yspeed,xspeed)` heading, owner slot/generation, type. |
| `VISIBLE` | `XtkExplosionView` | `Eset` entries in the viewport | array-index id, kind, position. |
| `VISIBLE` | `XtkLandmarkView` | `real_map` **inside the viewport only** | `type != NORMAL`, box-centre position. Currently visible geometry only. |
| `MAP` | `XtkMapCell` | own `Mapper` record only | grid cell whose persisted `flags/type/team/strength` is non-zero; unexplored cells omitted. |
| `RADAR` | `XtkRadarBlip` | own ordinary `Radar` record while `SP_on` | position, `age = 23 - life`, `classification = anonymous`. |

Key negative rules: `MapCell` is the controlled player's remembered knowledge,
so legitimate stale walls survive until the mapper revisits a box; mapper
knowledge is **not** synonymous with currently visible geometry, and `real_map`
is never copied wholesale. `Blip.flags` (the `ANY_VEHICLE` bitmask) is discarded
so anonymous contacts carry no live identity/location. Expired contacts are
already absent from `Radar.num_blips`.

### Death camera

When the controlled vehicle is not alive, `SelfState` still exports the frozen
last armor/ammo/score and not-alive flags, the camera centre is the dead
vehicle's frozen last `Loc`, and the dead vehicle is not a `VehicleView`. The
mapper/radar records freeze exactly as the legacy per-vehicle specials do. On
respawn the same slot is re-activated and `generation` advances, so a client
snaps rather than interpolating through death (P2.11).

## Read-only proof

- **Static scan** (`view.sh`): `server_view.c` contains no call to any
  `do_special`, `update_specials`, `update_vehicle`, `kill_vehicle`,
  `make_bullet`, `server_step`, `animate`, `intent_*`, `play_*`, `draw_*`, RNG or
  `explode_*` function. It dereferences existing records and copies fields only.
- **Runtime wrap** (`view_fixture.c`): a `--wrap=do_special` counter is asserted
  to be `0` across all 23 fixture exports.
- **State hash** (`view_fixture.c`): an FNV hash over the relevant authoritative
  globals (`frame`, vehicle/dead/alive counts, `actual_vehicles`, `real_map`,
  `Bset`/`Eset` arrays and counts, `special_stats`, and each vehicle's `Mapper`
  and `Radar` records) is unchanged across **0, 1 and 5** exports of the same
  tick.
- The only non-simulation value read is the read-only S1.11 instrumentation
  counter `special_stats.mapper_updates`, used as `map_revision`.

## Deferred / notes

- **Entity lifetimes and events** (`DEATH`, `RESPAWN`, `SCORE`, `MATCH_END`,
  transient effects) are P2.6; `generation` here is the provisional read-only
  `Combatant.deaths + 1` proxy. P2.6 replaces it with a dedicated export-side
  entity-lifetime counter; the key *shape* `(kind, id, generation)` is unchanged.
- Client-side interpolation/camera and stale-history rules are P2.11/P2.13; the
  exporter deliberately does not encode interpolation policy.
- **Owner review** of the field/visibility table in `docs/VIEW-v1.md` (including
  the map and death-camera behavior) is required before this table is treated as
  approved; any widening of the field set is a new D2-C schema decision.
- Full terminal-free-through-network parity and the actual socket/ENet path are
  P2.7/P2.15; `view.sh` exercises the shipped display-free core directly, not a
  transport.
