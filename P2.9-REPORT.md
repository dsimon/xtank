dependency audit + G).** The **native Windows 11 runtime proof is NOT collected**

## Goal

An SDL3 window/event/timer/renderer shell plus the portable Protocol-v1 codec and
pinned ENet transport, built on Linux for Windows 11 x64 with isolated outputs,
without linking any simulation, bot, ucontext/threader, X11, or Unix loader, and
without disturbing the Phase 1 server/oracle toolchain and flags.

## Wine runtime smoke (supplemental) — PASS

Wine is **not** the Phase 2 exit evidence; it is a Linux-side cross-target
runner. Runs used the Xvfb display and Wine's `windows` video driver with the
`direct3d` renderer.

| Run | Result |
| --- | --- |
| Linux native (`SDL_VIDEODRIVER=dummy`) | `WINDOWS-SMOKE PASS` (86 checks, 0 failures) |
| Wine MinGW exe @ 100 % DPI | `WINDOWS-SMOKE PASS` (86 checks, 0 failures) |
| Wine MinGW exe @ 150 % DPI | `WINDOWS-SMOKE PASS` (82 checks, 0 failures; scale reported 1.50) |
| Wine MinGW exe @ 200 % DPI | `WINDOWS-SMOKE PASS` (82 checks, 0 failures; scale reported 2.00) |
| Wine `--frames 120` (open/resize/render/close) | `FRAMES PASS (120 frames)` |

The self-test covers: window open + positive drawable size; injected keyboard
(down/up/keycode) and mouse (motion, button down/up, coordinates); resize to a
new logical size with a resize event; monotonic timer; 60 rendered frames; the
DPI transform at 1.0/1.5/2.0; decode/re-encode of all **15 committed protocol
golden fixtures** (`73 checks`); and a **real ENet UDP loopback connect** with a
HELLO/WELCOME codec exchange.

**Real server connect (Wine client → P2.8 network server).** The P2.8 opt-in
`Src/xtank-server-net --listen 40011 --fast` was started display-free on this
host; the Wine-built client connected and completed the handshake:

```
CONNECT OK 127.0.0.1:40011
WELCOME OK
CONNECT PASS   (exit 0)
```

**DPI caveat (Wine host limitation, not a client defect).** Wine's DPI emulation
*reports* the display scale (1.50 / 2.00 via the `LogPixels` registry value) and
the pure `logical↔drawable` transform is asserted at 100/150/200 % by the
self-test, but Wine does not expose a scaled pixel backbuffer
(`SDL_GetWindowSizeInPixels == SDL_GetWindowSize`). The self-test therefore
verifies the `drawable == logical*scale` integration assertion where the host
provides a scaled backbuffer (verified at 100 %) and prints a note otherwise.
Confirming that integration at 150/200 % is a native-Windows item below.

### Sandbox transport shim (test-only)

This CI sandbox's seccomp filter denies `sendmsg()`/`sendto()` with an explicit
destination (P2.7/P2.8 note). The test-only `Tests/phase2/sandbox_sendmsg_shim.c`
(`LD_PRELOAD`) connects the datagram socket and retries with `send()`; it was used
for both the loopback and the real-server runs here. It is not part of any
shipped client, and on a host with unrestricted UDP it is a no-op.
