## Goal

Export generation-safe entities, ticked events and results captured before the
score reset, using simulation transitions as truth. The protocol-v1 stable
presentation key is `(epoch, kind, id, generation)`; P2.5's `generation` was the
provisional read-only `Combatant.deaths + 1` proxy. P2.6 replaces it with a
dedicated export-side entity-lifetime counter and adds the event/results seam
the network session (P2.8) delivers.

## Entity lifetimes (generation-safe)

- **Dedicated counters.** `veh_gen[slot]`, `bullet_gen[array index]` and
  `exp_gen[array index]` are the only source of `generation`. They are monotonic
  and are deliberately **not** reset on an epoch change (the epoch is part of the
  key, so an identity can never collide across epochs).
- **Vehicles** advance on every new life in `activate_vehicle()`. The view and
  result records read the counter, never a pointer or `deaths`.
- **Bullets/explosions** have no mutation-site hook available (the plan permits
  only `animate/vehicle/game.c`); their generations advance in the end-of-tick
  observation when a previously-absent slot appears or a present slot changes
  identity, i.e. slot reuse. No pointer is stored in any DTO.
- The P2.5 `view.sh` assertion `self.generation == deaths + 1` still holds for a
  first life (both are 1); `view.sh` remains green.

## Events (derived from simulation transitions as truth)

| Event | Source | Rule |
| --- | --- | --- |
| `DEATH` | `kill_vehicle()` hook | `aux0` = killer slot (`0xFFFFFFFF` for none); key is the dying life's generation. |
| `RESPAWN` | `activate_vehicle()` hook | Emitted only for a life after the first; `aux0`/`aux1` = spawn `x`/`y`; key is the new generation. |
| `SCORE` | end-of-tick read-only diff | `aux0` = signed delta (two's complement), `aux1` = new total; per owner. |
| `EXPLOSION` | end-of-tick transient diff | `aux0` = explosion kind; a reused slot emits a new event with the advanced generation. |
| `MATCH_END` | `game_finalize_scores()` hook | `aux0` = winner slot (or `0xFFFFFFFF`); captured with RESULTS. |

The event buffer is bounded (`SERVER_EVENTS_MAX = XTK_MAX_PENDING_EVENTS`) and
drops beyond the bound; each event carries a unique, monotonic
`event_sequence` reset to 0 each epoch, giving the protocol dedup key
`(epoch, event_sequence)`. **No event is ever fed back into the simulation and
no event scores.** Observation is idempotent within a `frame`, so observing
zero, once or many times per tick emits neither duplicate events nor simulation
changes.

## Results captured before the score reset

`server_events_capture_results()` is called from `game_finalize_scores()` (the
P1.14 shared path used by both `game_results()` and `display_game_stats()`),
while `Combatant.score`/`name` still exist. It copies `end_tick`,
`result_kind` (win if `GAME_RESET` with a winner, else abort), `winner_slot`,
and one `RESULT_ENTRY` per combatant (slot, lifetime generation, score, bounded
NUL-terminated name) into the immutable `XtkResults`, then emits `MATCH_END`.
The results are retained until `server_events_reset()` starts the next epoch.

Two complete match epochs over one terminal-free human plus one drone assert:

- **forced slot reuse**: a forced bullet life in array slot 3 advances the
  generation on appearance and again when the slot is reused by a different
  life; a forced explosion slot likewise advances and emits a fresh ticked
  `EXPLOSION` each reuse;
- **death/respawn**: `kill_vehicle(hv, NULL)` emits `DEATH` with the dying
  life's generation; the respawn advances the counter by exactly one, emits
  `RESPAWN` with the new generation, and `server_view_export()`'s
  `self.generation` tracks it;
- **two epochs**: the epoch accessor advances and the event sequence restarts at
  0 in each epoch; lifetimes stay monotonic across epochs;
- **early win exit**: awarding the winning score drives `GAME_RESET`;
  `game_results()` captures `RESULTS` with `result_kind == 0`, `winner_slot == 0`
  and the winning (not reset) score before zeroing; a `MATCH_END` event appears;
- **duplicate/reordered delivery**: a scoreboard consumer applying the `SCORE`
  stream once, and again twice in reverse order with `(epoch, sequence)` dedup,
  produces identical boards, and the event-derived total equals the award — no
  double scoring;
- **read-only parity**: a simulation-state hash is unchanged across 0/1/5
  observations of the same tick.

`events.sh` also statically proves `server_events.c` calls no
draw/special/RNG/control/`server_step`/`make_bullet`/`explode_location`

## Constraints honored

- Event counters advance no RNG and change no rule; the hooks are read-only
  appends. Proven by G byte identity and the fixture's state hash.
- No scoring is derived from events (the fixture's consumer is a test-only
  model; production scores remain `Combatant.score`).
- No DTO carries a pointer; results are copied before reset, and no simulation
  pointer is read after `server_match_reset()`/cleanup.

## Deferred / notes

- **HIT** (protocol `XTK_EV_HIT`, `aux0` side mask / `aux1` damage) is not
  emitted: the plan's "relevant transient visual effects" are covered by
  `EXPLOSION`, and a HIT capture would need a reviewed per-damage-site hook
  outside the permitted files. It can be added in P2.7/P2.15 without a schema
  change.
- **Session integration** is P2.8: it will call `server_events_reset(epoch,
  first_tick)` at each `EPOCH_BEGIN`, `server_events_observe()` after each
  `server_step()`, and deliver `server_events_event()`/`server_events_results()`
  reliably on channel 0. Network delivery/dedup and the bounded pending-event
  window are P2.7/P2.8.
- **Bullet/explosion generation** detection is end-of-tick and therefore
  observes reuse only when the slot is seen absent then present (or changes
  identity); a remove+re-add with an identical signature within one tick is
  indistinguishable. This is an inherent limit of a read-only, no-bullet-hook
  design and is documented for P2.15.
- Client-side application of events/results, interpolation and stale-history
  rules are P2.11–P2.14.
