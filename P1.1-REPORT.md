Baseline instrumentation (`Src/animate.c`, +132 lines): a read-only FNV-1a
per-frame state oracle compiled only with `-DSTATE_DUMP`. It emits a line per
vehicle plus a world hash every `XTANK_DUMP_PERIOD` frames and unconditionally
when the game leaves `GAME_RUNNING`. An optional `XTANK_TICK_LIMIT` stops after
the boundary dump for a deterministic finite replay bound (used for the Madman
65,600-tick capture; default off, so the canonical dumps are unchanged). It
reads state only and cannot perturb a match.

`build-reference.sh` treats the manifest as authoritative: if the reference
binary is present but its SHA-256 no longer matches `binary_sha256`, it refuses
to run and instructs a deliberate `XTANK_P1_REBUILD=1` rebuild. The candidate is
always re-snapshotted from the current working tree, so it can never be
mistaken for the frozen reference.

## Xvfb robustness (the previous session's blocker)

The interruption was environmental: `Xvfb :99` had died, leaving the harness
pointing at a dead display ("Could not open display named :99"). The harness no
longer assumes `:99`:

- It probes `:90`–`:99` for a genuinely free display (lock file, socket, and
  live `Xvfb` process all checked) and starts its **own** `setsid Xvfb` with
  `-screen 0 1024x864x24 -nolisten tcp -noreset`.
- It waits (up to 10 s) for `xdpyinfo` to succeed before running anything, and
  aborts with the Xvfb log path if the server dies during startup.
- It records the PID, cleans up **only that PID** on exit (`--keep-xvfb` opts
  out; `XTANK_REGRESSION_DISPLAY=:N` reuses an external server).
- The `xkbcomp` keysym warnings in the log are non-fatal and expected.
