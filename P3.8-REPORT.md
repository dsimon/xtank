## 3. Implementation

### 3.1 Per-player view (view isolation)

`server_view_export(slot, generation, ...)` derives the camera **only** from the
controlled vehicle's slot — there is no arbitrary-centre or full-map API. It is
strictly read-only (no draw/special/RNG/control call) and leaves simulation
state byte-identical over 0/1/5 exports. Each recipient therefore gets its own
camera (viewport), its own `Mapper` knowledge (`MapCell`; never `real_map`), its
own radar blips (always anonymous) and its own `SelfState` HUD. `map_revision`
is recipient-local. All entity generations are read full-width (u32) from the
entity-life counter and `LandmarkView` carries the full `grid_x`/`grid_y`/`id`.

### 3.2 Authorized, bounded event delivery

`server_events.c` captures events into a bounded per-epoch ring
(`SERVER_EVENTS_RING = 512`) with a monotonic capture ordinal and a read-only
export-side occurrence location. `server_events_authorized()` applies the
D3-C recipient table:

| Event | Recipients |
| --- | --- |
| `SCORE` | own slot only (public only at `RESULTS`) |
| `DEATH` | victim and killer |
| `RESPAWN` | owning slot always; others only inside the reference viewport |
| `EXPLOSION` | only inside the reference viewport |
| `MATCH_END` | every admitted recipient |

`server_session.c` delivers per recipient: it reads every retained ordinal in
order, **skips** unauthorized private events without consuming a sequence
number, and rewrites `event_sequence` to the recipient-local contiguous value.
`capture_tick` is the occurrence tick written at capture and is preserved
through delayed delivery; the envelope `tick` is the delivery frame.

Bounding and failure:

- a cursor (`ev_cursor`) tracks the next ordinal; a cursor below the oldest
  retained ordinal means retirement outran the recipient and the peer is failed
  explicitly through the P3.7 departure path (`XTK_ERR_QUEUE_SATURATED`) —
  never silently dropped;
- a transport send failure returns 0 from `session_emit`, does not advance the
  cursor or the sequence, and fails the peer;
- the ring is sized above worst-case single-tick production, and `RESULTS` are
  also carried on the reliable control path, so no required lifecycle/result is
  lost.

### 3.3 Results

`RESULTS` are captured once per epoch, before the per-match score reset, by the
existing reviewed read-only hook in `game_finalize_scores()`; the P3.8 fix
carries the full-width u32 entity-life generation. Results include every
retained participant (departed included, with `XTK_FLAG_DEPARTED`), are
immutable copies, and survive later departures.

## 6. Stop-condition assessment

None triggered:

- **Private event leakage:** the recipient table delivers `SCORE` own-only,
  `DEATH` to participants, `RESPAWN`/`EXPLOSION` only in the reference viewport,
  and no remote private field is exported (asserted by both fixtures).
- **Export mutation/RNG/draw access:** static scans of
  `Src/{server_events,server_view}.c` find no draw/special/RNG/control call, and
  0/1/5-observation/export parity holds.
- **Generation truncation/alias:** the last truncation (results entry) is
  removed; generations are u32 end-to-end and a >255 life is not truncated.
- **Silent overflow / send failure marked delivered:** retirement below a cursor
  and a transport send failure both fail the peer explicitly and never advance
  the delivered sequence.

No minimal reproducer or scope question is required.
