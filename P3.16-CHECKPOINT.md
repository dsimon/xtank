## Findings

- **F1 (fixed, build portability).** The P3.16 gate's required MinGW-w64
  cross-build of the shipped client failed: `Transport/enet_transport.c`
  (P3.13 timing instrumentation) called `clock_gettime()`, which the pinned
  MinGW-w64 **win32-thread** model neither implements nor links without
  libwinpthread (forbidden by D2-D). Minimal reviewed fix: `tx_now_ns()` uses
  the monotonic Win32 `QueryPerformanceCounter` under `_WIN32`, `clock_gettime`
  elsewhere. Off-by-default read-only timing; Linux/server and the frozen
  simulation are unaffected.
- **F2 (reconciled, inherited Phase 2).** The P3.3 exact-version-1.1 bump
  supersedes the v1.0 byte-golden Phase 2 drivers. Probed post-v1.1: valid
  (PASS) = protocol (v1.0 independent verifier), players, events, assets,
  timeline, input, playable; superseded = codec (v1.0 goldens), view
  (`SelfState.reserved` scalar), transport (documented wall-clock `paused-reader`
  flake), session (solo epoch/abort semantics changed by P3.4), ui (segfault on
  changed client structs), parity (P3.12 successor). The gate runs the valid P2
  drivers, records each superseded driver as `SUPERSEDED` with its required
  Phase 3 successor, and `require_successors` fails the gate if any successor is
  not PASS. Nothing is silently dropped; v1.0 fixtures remain verified (P3.3).
- **F3 (host prerequisites, installed).** Fresh VM lacked `flex`, `xdpyinfo`,
  `xrdb`, MinGW-w64. Installed flex 2.6.4, x11-utils, x11-xserver-utils and the
  pinned MinGW-w64 toolchain; all added to the gate's prerequisite check so a
  missing tool BLOCKS (never PASSes).
