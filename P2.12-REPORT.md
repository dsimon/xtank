## Goal

The client input controller: keyboard/mouse edge triggers, held controls, a
15 Hz emit on the network tick, correct mapping to drive/fire/weapon/aim, a
pause that is only meaningful outside a Running match, and unconditional
release of every held control on quit or window defocus — with SDL scancodes
and server intent codes kept strictly separate, no emit on tick 0, and no
blocking call anywhere in the input path.

## Design

- **Three separated vocabularies.** `platform_sdl.c` maps an SDL scancode or
  mouse button to a neutral `XtkControl`; `input.c` maps a control to a frozen
  wire `XtkCommandOp`; the server (P2.7) maps that wire op to the engine
  `IntentOp`. No translation unit ever sees two of the three, so a raw
  keyboard state cannot reach the engine.
- **Edge vs held.** Held drive (W/S, arrows) and fire-hold (Ctrl) refresh every
  tick and emit exactly one neutral release (`a = 0`) when lifted. Fire (Space
  or left mouse) and weapon selects (1–6) are latched edges: a press produces
  one command with a unique `command_id`, survives a sub-tick press/release,
  and is never re-produced a second time.
- **15 Hz, tick 0, heartbeat.** `input_emit(server_tick)` returns nothing for
  `server_tick <= 0` or when the state is not Running. While Running it returns
  one `XTK_INPUT_BATCH` per tick; when no control is active it emits a single
  `HEARTBEAT` so the approved two-second solo-abort never fires on an idle
  client. `packet_sequence` is monotonic per session.
- **Redundancy.** Each batch prepends the previous `XTK_INPUT_REDUNDANCY_TICKS`
  (2) tick batches, oldest tick first so the server preserves admitted order,
  bounded by `XTK_INPUT_MAX_BATCH` (32). An edge fires once but is retransmitted
  only inside that window (gone after tick + 2). The server deduplicates by
  `command_id`, so a channel-2 copy can apply first without a second fire.
- **Pause / quit / defocus.** Pause toggles only outside Running and never
  emits gameplay. Window focus loss releases every held control unconditionally
  (a stuck control must not outlive focus); an explicit `quit` request also
  releases immediately and is sticky. Leaving Running clears all held/edge/aim
  state and the redundancy ring, so no prior-match command can leak into a new
  epoch.
- **World aim transform.** `input_screen_to_world()` is the exact inverse of the
  P2.10 renderer transform (`screen = world - (center - viewport/2)`), scaled by
  the P2.9 DPI factor. It is pure and cannot request a camera region beyond the
  authorized own-pose window.

## Constraints honored

- SDL scancodes (`platform_sdl.c`) and server intent codes (`Src/Include/intent.h`)
  never meet: `input.c` uses only neutral `XtkControl` and frozen wire ops.
- Never emits on tick 0; never emits gameplay outside Running; idle Running
  ticks emit a heartbeat.
- Never blocks: `input.c` performs no I/O, sleep, poll or allocation.
- Releases all held controls on quit and window defocus; pause is only honored
  outside Running.
- No simulation file touched; the X-boundary and frozen oracle are unchanged.

## Deferred / notes

- **Wiring into the live session loop is P2.14.** `main.c` exercises the
  controller in `--self-test`; the real per-tick `input_emit` call, mouse
  screen→world feed and focus→`input_set_focus` edge wiring belong to the
  playable integration task, as do HUD/map/radar (P2.13).
- **Weapon semantics** are a network release subset: a number key emits
  `XTK_OP_WEAPON` with `b = 1` (enable) as an edge. Full on/off/fire toggling
  and UI weapon selection are left to P2.13/P2.14.
- **Steering** is mouse world-aim (`AIM_WORLD`); the release UI has no
  target-chase/chase/standoff controls, which remain test-only per PROTOCOL-v1
  §6.
- The redundancy window means a one-shot edge is retransmitted for up to two
  ticks (the protocol's freshness policy); duplicate suppression is the
  server's P2.7 responsibility, verified here at the command-id level.
