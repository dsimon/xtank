## Design

The act of "initializing geometry" was previously entangled with pixmap
creation in `Display/objects.c` and duplicated between the two backends
(`Display/x11.c` and `Display/null.c`). P1.10 splits it:

- **`Src/geometry.c` (new, shared by both builds)** owns everything with no
  video dependency:
  - `geometry_order_objects()` assigns `vehicle_obj`/`turret_obj`/`exp_obj`/
    `bullet_obj`/`landmark_obj`/`random_obj` and the `num_*` counts;
  - `geometry_rotate_object()` / `geometry_rotate_objects()` compute the 12
    derived views from the base 4, using the 90°/180° bitmap math moved
    **verbatim** from `Display/x11.c`;
  - `geometry_upload_objects()` performs the backend pixmap upload
    (`make_picture`) **separately** from the pure geometry, so the server path
    can initialize geometry with no pixmap at all;
  - `geometry_dump(FILE *)` emits the explicit table;
  - `geometry_test_dump()` is the env-gated harness hook
    (`XTANK_GEOMETRY_DUMP` writes the table, `XTANK_GEOMETRY_EXIT` stops right
    after it). Unset, it is a no-op.
- **`Display/objects.c`** now holds the single body/bitmap registry
  (`geometry_objects[]`, the only place the static `.obj` names are visible)
  and `make_objects()` becomes `order → upload → (optional dump)`. The legacy
  sequence and indices — including the pulse-laser bullet alias at index 18 —
  are preserved. `rotate_objects()` delegates to `geometry_rotate_objects()`.
- **`Display/x11.c`** keeps only the X upload path (`make_picture`); its
  rotation functions and `reverse_byte` table were removed.
- **`server_core.c`** calls `geometry_order_objects()`/`geometry_rotate_objects()`
  from `server_match_init()`, so a display-free entry that builds no terminal
  still has geometry. Both calls are idempotent, so the existing X flow (which
  already ordered/rotated in `main()`/`make_terminal()`) is unchanged.
- **`Makefile.inc1`** and **`Tests/phase1/build-reference.sh`** add
  `geometry.c` (67 X-free server TUs, was 66).

Turret coordinates and collision segments are read-only data in the `.obj`
files (`Object.picinfo`); P1.10 exposes them through `object.h` and the dump but
does not convert or recompute them.

## Geometry table

The table is emitted for every object category and every rotation:

```
obj <kind> <index> type <name> pics <n> turrets <t> segs <s>
  pic <r> w <w> h <h> ox <ox> oy <oy>
    turret <t> x <x> y <y>
    seg <s> x1 .. y1 .. x2 .. y2 .. dx .. dy .. slope .. intercept .. minx..maxy
```

It deliberately excludes the `pixmap` field: that is the only backend-specific
part of `Picture`, so the X (real pixmaps) and server (no allocation) runs can
be compared byte for byte. Counts: `vehicle 14 turret 1 explosion 10 bullet 25
landmark 3 random 3`.

views 4–7 from views 0–3 (`w=h`, `h=w`, `ox=h-oy-1`, `oy=ox`) and views 8–15
from views 0–7 (`w,h` unchanged, `ox=w-ox-1`, `oy=h-oy-1`) and requires exact
agreement.

## Deferred / notes

- `rotate_object`'s prototype in `Src/Include/proto.h` is now unused (the
  function was absorbed into `geometry.c`); the stale prototype is harmless and
  was left alone to keep the change inside the P1.10 file set. The same header
  still declares `rotate_pic_90`/`rotate_pic_180`, which remain defined only by
  the null backend (`Display/null.c`); they are now dead on the server path and
  can be removed when `null.c` is next revised.
- `Display/null.c` was intentionally not edited: the pure rotation math now
  lives in `geometry.c` under `geometry_*` names, so the null copies are dead
  code rather than duplicate symbols.
- `collision.c` needed no change: it consumes only `Picture` geometry
  (`width`/`height`/`offset_*`) and `Object.picinfo`, which are now initialized
  without video. No formula was touched.
- The registry/ordering remains in `Display/objects.c` (that is the only place
  the static `.obj` names are visible); `geometry.c` consumes it. Moving the
  `.obj` includes themselves is out of scope and would be a content change.
- `XTANK_GEOMETRY_DUMP`/`XTANK_GEOMETRY_EXIT` are test-only; production runs
  never set them and behave exactly as before.
- flex 2.6.4 was installed on the host (the plan requires it). An earlier
  G-before attempt left a zero-length generated `setups.c` in the reference
  snapshot, which the harness's existence check then skipped; removing it and
  regenerating fixed the reference build. No source was affected.
