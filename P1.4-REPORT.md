## Routing summary

- **Drawing/text:** callers → `draw_*` (graphics.c) → `graphics_backend->draw_*`
  → `x11_draw_*`. Encapsulated direct `XDrawArc`/`XDrawLine` are now reachable
  only through the vtable.
- **Window flags:** `win_exposed`/`win_mapped`/`video_win_flags`/`expose_win`/
  `color_display` (graphics.c) → vtable ops (`win_flags`, `mapped`,
  `expose_win`, `color_display`).
- **Beep/flush/sync:** `beep_window`/`flush_output`/`sync_output` → vtable.
  `multi_sync` remains an X-specific backend routine (called via `proto.h`).
- **Preferences:** already accessors (`video_*`), unchanged from P1.3 and
  documented as the preference routing path.
- **Batching:** `flush_point_batch`/`flush_line_batch` remain empty no-ops in
  this build (`USE_BATCHED_*` undefined) exactly as in the pinned/legacy build;
  the draw entry points now sit in front of the backend, so enabling real
  batching later is backend-local and does not touch callers.

## Input semantics

The only `X11`-conditioned behavior in the presentation input path was the
`button_up`/`follow_mouse` toggling. Those conditions are now named
`GRAPHICS_POINTER_INPUT_ALWAYS_ON` (set by the X presentation backend), so
removing `-DX11` from server compilation (P1.5) cannot silently change X input
handling. The X frontend build defines it exactly as before.
