## New `graphics_backend.h` contract

- **Neutral geometry:** `GraphicsPoint {short x,y}`, `GraphicsSegment {short x1,y1,x2,y2}` — layout-compatible with `XPoint`/`XSegment`.
- **Neutral flags/constants:** `WIN_exposed`, `WIN_mapped`, `DRAW_XOR`, `DRAW_COPY`, `MAX_DRAW_FUNCS`.
- **Opaque presentation type:** `typedef struct video Video;`.
- **Backend operations:** `GraphicsBackend` with function pointers for points/lines/rects/squares/pictures/arc, text (left/centered/row-col), beep/flush/sync, window flags/expose/mapped, color-display, and font metrics; `extern GraphicsBackend *graphics_backend` is installed by the X backend.
- **Neutral drawing API:** the former `x11.h` macros are now real functions declared here and implemented in `x11.c`, so callers never need `x11.h`.
- **Accessors:** window/preference/state accessors replacing direct `Video` field reads; `DEST_WALL`/`RDF_SAFE` are lvalue accessor macros (`*video_dest_wall()`), preserving assignment in the X backend and reads in `camo.c`/`display.c`/`mapper.c`.

## Behavioral fidelity notes

- `USE_BATCHED_LINES`/`USE_BATCHED_POINTS` are `#define`d in `display.c` *after*
  `graphics.h` (and therefore `x11.h`) is processed, so the legacy macros were
  already the non-batched direct-X versions and `flush_*_batch` was already
  empty in this build. The new draw functions perform the identical direct X
  calls, and `flush_point_batch`/`flush_line_batch` remain empty — no rendering
  behavior change.
- `expose_win` returns `int` (the post-update window flags) so the existing
  `check_expose` comma-expression in `gr.h` still compiles and evaluates as
  before.
- `<assert.h>` is now provided transitively via `graphics_backend.h` (it was
  previously provided by `x11.h`), matching prior include behavior for
  `assert()` users.
