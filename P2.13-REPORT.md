## Design

- **Snapshot/DTO driven.** `hud_build` takes `XtkSelfState`; `map_build`/
  `radar_build` take `XtkViewSnapshot`; `menu_build_lobby`/`_results` take the
  reduced lobby state / immutable `XtkResults`. No module reads a simulation
  global, `real_map`, `actual_vehicles`, a `Terminal` or a pointer.
- **Scene, not pixels.** Each builder emits a bounded `XtkUiScene` of text/
  rect/line primitives; `render_frame_ui` bakes it onto an ARGB surface with a
  portable built-in font (exact X glyphs are backend-owned, P2.10 note). This
  keeps the modules unit-testable and the screenshot path reusable in P2.14.
- **Anonymity.** The HUD/map/radar never read `owner->name`/`player_name`
  (scanned by `ui.sh`); the radar carries only anonymous `(x,y,age,
  classification)` and discards `Blip.flags`. Public names are read only in
  `menu.c` for the `RESULTS` entries (`VIEW-v1.md` §4.8).
- **No full map.** `map_build` draws only exported `MapCell` knowledge; a
  remembered wall that no longer exists in the world is preserved exactly as
  the server sent it (`VIEW-v1.md` §5.3/§4.6), and unexplored cells are absent.
- **Wiring.** `menu_apply_message()` is the presentation-side protocol
  reduction; `RESET`/`EPOCH_BEGIN` clear only the retained results, the catalog
  and selection survive.

### Sandbox tool shims (test-only, outside the checkout)

This execution environment lacks `flex`, `xdpyinfo` and `xrdb` (no install
candidate; the P2.1 toolchain was not present in this session), which the
reference build/oracle need. To run G the oracle was given three test-only
stand-ins in `/tmp/opencode/xtank-phase2/p2.13/bin`:

- `flex`: serves the working tree's already-generated Phase 1 `setups.c`/
  `lex.zz.c` (the reviewed `.l` edits are behavior-neutral — the same tree
  passed G in prior tasks). Served from a stable copy so a caller's shell
  redirect cannot truncate the source.
- `xdpyinfo`: succeeds iff the local `X :N` socket exists (Xvfb readiness).
- `xrdb`: a small libX11 tool that sets the `RESOURCE_MANAGER` root property
  from stdin (the harness merges `xtank.playerName: playerA/B` for the two
  display v2 human trace; without it both terminals collide and the reference
  aborts).

No harness, golden, seed or simulation source was modified; the shims only
substitute missing host tools. They live outside Git.
