## Goal

Portable, checked export of the original body/turret/projectile/explosion and
landmark visuals (plus the palette/font and the 16 body views) into a client
asset bundle, and a snapshot-driven full-frame renderer that draws a protocol-v1
`VIEW_SNAPSHOT` at the original 2D scale, offsets, turret placement and rotation
indexing, without linking any simulation or legacy world-reading renderer.

## The bundle and the exporter

`Tools/export-client-assets.c` links no simulation, no graphics backend and no
X11; its only engine includes are the data-only object descriptions
(`tanktypes.h`, `tanklimits.h`, `vehicleparts.h`, `object.h`) and the `.obj`
sources. It emits a deterministic little-endian bundle (64-byte header +
payload):

- 8 counts (vehicle/turret/explosion/bullet/landmark/random/palette/font), a
  payload length and an FNV-1a checksum;
- the 11-entry palette (`Src/Display/x11.c` `colorname[]`) resolved to sRGB;
- the 5 font identities (`fontname[]`) with nominal metrics;
- every object in registry order: type string, view/turret/segment counts,
  per-view pictures (1-bit MSB-first stencil + width/height/offset), per-view
  turret coordinates and collision segments.

Vehicle bodies carry only 4 base views in the `.obj`; the exporter derives views
4–7 (90°) and 8–15 (180°) with the exact `geometry_rotate_pic_90/180` math from
`geometry.c`, including the same offset formulas. The pulse-laser alias bullet
(index 18, `NULL` bitmap) is preserved as geometry-with-no-bitmap. Turret
coordinates and collision segments are copied verbatim from `Object.picinfo`.

The exporter is a Linux host tool (it uses POSIX `open_memstream` to size and
checksum the payload); the bundle it writes is the portable artifact. Bundle:
**180 274 payload bytes**, FNV-1a `03358bb1`, SHA-256
`9141e3b9…da7e81`. Two exporter runs are byte-identical.

## Visual fixture results

`Tests/phase2/assets_fixture.c` links `assets.c` + `render_sdl.c` + SDL3 and no
simulation. **215 checks, 0 failures.**

- **Exact scale/art**: an isolated body is drawn into a 768×768 ARGB surface
  with the camera centred on it; every set bitmap bit must land on exactly its
  screen pixel (`point − offset + bit`, 1 world unit = 1 pixel) and every clear
  bit must stay background. This fails on any scale or offset error.
- **Turret placement**: Marauder body view 3 + turret view 5 — the turret is
  drawn at the body's per-view `picinfo` `turret_coord[0]`, verified at a set
  turret-bit pixel.
- **Bullets / explosions / landmarks**: drawn at their world positions (bullet
  rotation via the replicated legacy `find_rot()`).
- **No trails**: frame A then frame B on one surface equals a from-scratch frame
  B (a moved entity leaves no pixels behind); a render→render→render expose
  sequence equals a fresh render.
- **Resize**: the same pose into a 512×512 surface is still 1:1 (body at the
  512-centre, not scaled) and exact.
- **DRAW_XOR**: per-channel XOR (`bg ^ fg`), and drawing twice restores the
  background. The client never installs the legacy `GraphicsBackend` vtable, so
  no legacy caller's XOR semantics are redefined.
- **Checked load**: bad magic, truncation and a corrupt payload byte are all
  rejected by the loader.
- **Determinism**: repeated renders are byte-identical.

## Deferred / notes

- **Explosion animation frame** is not in the `VIEW_SNAPSHOT` DTO (P2.5 exports
  only `kind`/position; the legacy frame is `num_pics - life`). The renderer
  draws the object's last frame by default (`XtkRenderView.explosion_frame`
  overrides). Exact per-tick explosion animation belongs with P2.11/P2.13 once
  the snapshot carries the life/frame, or an event supplies it.
- **Per-vehicle color** is not exported (VIEW-v1 §4.2 authorizes no color); the
  renderer takes colors from `XtkRenderView`. The palette is exported for the
  later HUD/map work; a presentation color policy is P2.13.
- **Fonts**: only the legacy font *identities* (and nominal metrics) are
  exported — exact X font glyphs/metrics are backend-owned and not portable.
  Text rendering is P2.13.
- **Camera/interpolation** are deliberately not implemented here: the renderer
  draws a supplied `XtkRenderView` pose; the model/timeline/camera are P2.11.
- The shipped client's frame loop does not call the renderer yet (that wiring is
  P2.11/P2.14); P2.10's acceptance is the fixture.
- Evidence under `/tmp/opencode/xtank-phase2/p2.10/` (exporter/fixture builds,
  bundle, geometry tables, `assets` run, oracle before/after, `phase1-check.log`,
  client build trees). Not in Git; generated binaries/objects stay outside the
  checkout.
