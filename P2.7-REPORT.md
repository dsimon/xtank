## Goal

Provide a bounded, nonblocking ENet transport wrapper and the input-admission
seam that turns validated wire commands into engine intents — connection
ownership, finite/range validation, cross-packet/channel deduplication,
assigned-tick acknowledgments, and the bounded pre/post-step integration in the
shipped simulation loop. The engine is touched only on the simulation thread;
no blocking socket/DNS call happens inside a tick; no raw-UDP reliability is
implemented; `Src/intent.c` is unchanged.

### Ownership (P2.4 `ServerHumanBinding`)

The session owns `controller → slot → generation`; every command is checked
with `server_players_validate(controller, slot, generation)` before admission
and applied with `Intent.player = binding slot`. There is no wire field for a
peer-supplied player, and a bumped/rebound generation rejects the old
controller. Commands carry the running epoch in the envelope; a command from
another epoch is acknowledged `XTK_ERR_STALE_EPOCH` and has no effect. Edge
commands older than `XTK_CMD_EXPIRY_TICKS` are rejected rather than fired after
respawn/reset.

### Dedup, scheduling and acknowledgments

- Command ids are deduplicated session-wide across packet **and** channel
  boundaries (window `XTK_CMD_DEDUP_WINDOW`), so a channel-2 copy may apply
  first but the reliable channel-0 companion is acknowledged
  `XTK_ERR_DUPLICATE` and never applies twice. Replayed/older `packet_sequence`
  datagrams are ignored.
- Accepted commands are assigned to the next unconsumed engine tick, preserving
  admission order; the wire `tick_hint` is only a freshness hint (never
  backdates/reserves). `Intent.sequence` comes from an independent per-session
  counter, never the packet sequence.
- Each command yields an acknowledgment (`accepted` / `applied` / `rejected`)
  with the assigned tick and reason; post-step batches them into `CMD_ACK`.
- Saturation keeps `SERVER_NET_RELEASE_RESERVE` slots free: normal commands are
  rejected `XTK_ERR_QUEUE_SATURATED`, but release/neutralizing commands
  (drive 0, fire-hold 0, weapon off) are still admitted.

### Sandbox note (test harness only)

This CI sandbox's seccomp filter denies `sendmsg()` with an explicit
destination but allows a send on a connected socket, so ENet's UDP sends fail
with `EPERM`. `Tests/phase2/transport.sh` links the fixture with
`-Wl,--wrap=sendmsg`; `admission_fixture.c` connects the socket to the
destination once and retries. This selects an equivalent kernel send path and
changes no production code and no wire behaviour; on a host with unrestricted
UDP the shim is a no-op. The real ENet protocol, fragmentation, queues and
reliability are still exercised over loopback UDP.

## Constraints honored

- Engine accessed only on the simulation thread, inside the bounded pre-step
  point; `server_net.c` calls no draw/special/RNG/step function.
- `transport_service` uses a zero timeout (never blocks); address resolution
  happens only in `transport_connect`, outside ticks. Received packets are
  copied into a bounded queue and dropped/counted when full.
- No raw-UDP reliability: channels 0/1/2 are ENet `ENET_PACKET_FLAG_RELIABLE`
  or unreliable-sequenced. Reliable backlog is watched and the peer aborted at
  `XTK_MAX_RELIABLE_QUEUE_BYTES`.
- `Src/intent.c` untouched; `intent_consume` order is unchanged.

  own beyond the bounded pre-step's auto-session-on-connect; handshake, lobby,
  ownership assignment through `HELLO`/`WELCOME`, snapshot/event delivery and
  the two-second abort are `server_session.c`/`server_main.c` work. `server_net`
  is intentionally not in the standard source list until then.
- **Snapshot/event channel-1 delivery** joins P2.6/P2.8; P2.7 only flushes
  `CMD_ACK` and admits input. At most the newest unsent snapshot is a P2.8
  obligation.
- **HIT events** remain deferred (P2.6 note); unaffected here.
- **Full network-path parity** against the frozen X v2 dumps is P2.15; the
  admission fixture here proves the adapter, not the replay-equivalence audit.
