## 5. Healthy-LAN input-to-visible latency (p95 <= 250 ms)

**Method.**  Both clients and the server run in one process sharing
`CLOCK_MONOTONIC` (ns).  For each 15 Hz input command the fixture stamps the
send time, observes the server `CMD_ACK` (which carries the authoritative
`assigned_tick`) and then the first `VIEW_SNAPSHOT` whose `server_tick >=
assigned_tick`.  Latency = snapshot-arrival − send, same monotonic clock.  It
covers input → transport → admission → tick → export → client receipt, and
because the loopback link adds no propagation delay it is a **lower bound** on
a healthy LAN (real LAN gives the same order of magnitude).

Result: **p95 = 66.8–66.9 ms** (p50 66.7, p99 67.7–67.9, max 77 ms), 899
samples per peer per run — the latency floor is one 15 Hz tick plus the render
pump, comfortably below 250 ms.
