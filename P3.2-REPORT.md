## 1. Objective

Specify the minimal server-only removal seam **before** touching lifecycle code
and prove it can implement the approved departure policy while preserving every
ordinary simulation path:

- no forfeit winner, no mid-match bot adds (D3-D);
- departed combatants keep earned score/name with a departure marker (D3-D);
- stable records retained until outstanding projectile references and match
  cleanup complete (D3-D);
- removal distinct from a kill: **no** score / death / RNG / explosion / respawn
  side effect;
- ordinary (non-departure) simulation stays byte-identical.

## 3. Read-only inspection (the load-bearing primitives)

- **Live/dead lists** (`Src/animate.c`, `Src/vehicle.c`): `live_vehicles[]` /
  `dead_vehicles[]` are plain pointer arrays with swap-with-last removal
  (`animate.c:559,578`). `actual_vehicles[]` is a fixed static array; a vehicle
  pointer stays valid for the process even after it leaves both lists.
- **`inactivate_vehicle(v)`** (`vehicle.c:390`): clears `VS_is_alive`; runs
  `zap_specials` (only `do_special(SP_deactivate)`, which does **not** free the
  special records); kills program threads; clears the terminal binding (NULL for
  a terminal-free human); clears the vehicle's `flag` from
  `real_map[old_loc]`. It performs **no** explosion, `deaths++`, score change,
  RNG draw, or storage free, and is idempotent.
- **`kill_vehicle(v,k)`** (`vehicle.c:583`): calls `explode_vehicle` (many RNG
  draws), `deaths++`, score arithmetic, `explode_location`, and allows respawn.
  Unusable for departure.
- **`unmake_vehicle(v)`** (`vehicle.c:253`): frees `program[].thread_buf`,
  `stack_buf` and the special records with `unmake_specials`. Unsafe while a
  live projectile still references the owner (see next bullet).
- **Projectile owner references**: `Bullet.owner` (`bullet.h:98`) is read as
  `b->owner->number/team/status/loc/special[...]` across
  `update.c` (490,497,499,504,667-721,833-847), `hit.c` (445,485,499,536),
  `collision.c` (466-484) and `disc.c` (143-196). Retaining (not freeing) the
  vehicle's storage keeps every one of those reads valid; freeing its special
  records would be a use-after-free.
- **Team counts / rules** (`game.c`): `teamdata[].vehicle_count` and `num_teams`
  are game-rule state; `combat_rules` FFA scans the **live list**, so a removed
  departed tank is not scored or an end-condition trigger.
- **Pending/held input** (`intent.c`): the queue and the held
  `held_aim/chase/standoff/fire` arrays are per-player, but the **only** cancel
  primitive is `intent_reset()`, which clears *every* player and the whole
  queue. There is no player-scoped cancel.

## 4. Exact removal mutation / order / retention contract

Applied at a tick boundary (P3.7 chooses the precise pre/post-`server_step`
placement), **once per departure**, for the departing controller bound to slot
`s` with `v = &actual_vehicles[s]`:

1. **Validate** the departure (peer/session/epoch/life generation) in P3.6/P3.7
   before any mutation; malformed/stale/replayed traffic never qualifies.
2. **Cancel the departing peer's input** — a new player-scoped
   `intent_cancel_player(player)`: drop queued intents with `player == s`, clear
   held aim/chase/standoff/fire for `s`, reset `dw_*` for `s`. **Must not**
   disturb any other controller's queue or held state. *(New reviewed seam; see
   §5.)*
3. **Mark departed** in server state (P3.7 owned; e.g. a bounded departed
   record keyed by slot) and **unbind** the controller via the existing
   `server_players_unbind_slot(s)`.
4. If `v` is alive (`VS_is_alive`): call the existing **`inactivate_vehicle(v)`**.
   Do **not** call `kill_vehicle`/`explode_vehicle`/`unmake_vehicle`.
5. Remove `v` from `live_vehicles[]` (swap-with-last) and, if it is
   respawn-waiting, from `dead_vehicles[]`.
6. **Do not** alter `teamdata[]`, `num_teams`, scores, kills, deaths or any rule
   formula.

**Retention:** `actual_vehicles[s]`, `combatant[s]`, its name and earned
score/kills/deaths, weapon arrays and special records stay allocated and
field-consistent until normal `server_match_reset()`; this keeps
`Bullet.owner`/disc references valid. In-flight projectiles continue under
unchanged projectile rules (a departed tank's projectile may still damage or
even score for its retained combatant — explicitly allowed by D3-D/P3.7).
Respawn is impossible because `v` is in neither list.

**Cleanup (server layer, no `setup.c` change):** `game_cleanup()` frees only
`live_vehicles[]`/`dead_vehicles[]`, so a retained departed record must be
returned to that path. In allowed `Src/server_core.c`, keep a bounded set of
departed records and, in `server_match_reset()` **after the finished match's
projectiles are gone** (no `server_step` runs between reset and the next
`init_bset`), reattach each to the dead list before `game_cleanup()` — or drain
it with `unmake_vehicle()`. Either releases the storage through the existing
path; no `Src/setup.c` change is needed.

**Remaining tank/bot and end-of-match semantics:** removal is invisible to
ordinary rules. Remaining humans/drones keep progressing under unchanged
Combat; a natural 1000-point winner ends the match normally, and the departed
combatant appears in results with its retained score/name and a departure
marker. If no scored winner exists when ordinary rules end, the result is
abort/no-winner. If no humans remain, P3.7 cleans the world and returns to the
listening lobby (no in-simulation forfeit).

## 5. Result: do existing primitives suffice?

**Almost.** Everything except one operation is implementable with existing,
already-reviewed primitives and the already-authorized P3.7 files
(`server_session.c`, `server_net.c`, `server_players.c`, `server_core.c`,
`Include/server.h`):

| Requirement | Primitive |
| --- | --- |
| Make a live tank not-alive, without kill/score/death/RNG/explosion | existing `inactivate_vehicle()` |
| Remove from live/dead lists | existing swap-with-last (reimplemented in server layer) |
| Retain storage + valid projectile owner | already true (static `actual_vehicles[]`; no `unmake_vehicle`) |
| Clear map occupancy | `inactivate_vehicle()` clears `real_map[old_loc]` flag |
| Unbind controller / generation bump | existing `server_players_unbind_slot()` |
| Release retained records at match reset | `server_core.c` (already a P3.7 file) |
| No team-count / rule change | by construction (no mutation) |

**Smallest reviewed Src seam (one only):** a new
`intent_cancel_player(int player)` (+ declaration) in `Src/intent.c` /
`Src/Include/intent.h`. The fixture demonstrates the need concretely: after a
slot-0 departure, a queued/held fire for that slot is still accepted (storage
retained) and the departed tank **fires a ghost projectile**; the only current
cancel, `intent_reset()`, also wipes the surviving controller's held state. A
player-scoped cancel is therefore required for P3.6/P3.7 (D3-E already reserves
both neutralizations). No `animate.c` change is required: removing a departed
vehicle from both lists keeps it outside every animate pass.
