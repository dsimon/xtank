## Defects found and fixed

All were harness defects; no gameplay or simulation change was made.

1. **Terminal-tick score reset (fixture read timing).**  The shipped
   `server_session_step` finalises a finished match inside the call
   (`server_session_finish` → `game_results` → `game_finalize_scores`), which
   zeroes each combatant's per-match score *after* the tick snapshots/events
   are exported.  The frozen X reference dumps at the `game_rules` seam,
   before that zeroing, so a dump read after `server_session_step` differed
   only on the winning tick (`score 1000` vs `0`; every other field
   identical).  `parity_fixture.c` now recovers the captured pre-reset score
   from the immutable results (`server_events_results`, copied before the
   reset) before emitting a non-RUNNING tick.  Read-only; no state or tick
   changed.
2. **Lowercase maze name.**  `parity.sh` passed `arena` for the first
   scenario; the file is `Mazes/Arena.m` (`make_mdesc` is case-sensitive).
   Fixed to `Arena`.
3. **Unbounded non-terminating traces.**  The `*-2000` traces never reach a
   natural win, so `run_x` ran the reference unbounded (2.6 M ticks, a 7.2 GB
   dump) and timed out.  Added a finite replay bound (`XTANK_P3_TICKS`,
   default 4000) applied to *both* legs (`XTANK_TICK_LIMIT` for X and
   `XTANK_P3_TICKS` for the fixture).  Natural-win traces end earlier and are
   unaffected.
