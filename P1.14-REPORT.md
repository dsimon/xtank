## Loading design

### Explicit asset root (`Src/file.c`, `Src/Include/server.h`)

- `content_set_root(root)` installs a root and derives `Vehicles`, `Mazes`,
  `Programs` and `Src/Include` beneath it. It reads no environment variable,
  opens no display, and returns `-1` with `content_last_error()` when the root
  is missing, empty or not a directory.
- `get_environment()` resolves the root exactly once: `XTANK_ASSET_ROOT`
  (explicit) wins, otherwise the legacy `XTANK_DIR` (plus
  `XTANK_VEHICLES`/`MAZES`/`PROGRAMS`) is used unchanged, so the X front-end is
  unaffected.
- `content_load_maze()`/`content_load_vehicle()` load one named asset by
  explicit path under that root. They consult no list, draw nothing and never
  fall back to a random maze; a missing/malformed file returns a `DESC_*` code
  and a human-readable reason. `content_load_settings()` wraps `load_settings`
  with the same error reporting.

### List independence and no RANDOM fallback (`Src/setups.l`)

- `content_load_maze()` calls `load_mdesc()` directly, so `combat1.m` loads
  despite being absent from `Mazes/list`.
- The settings parser's `cv_maze()` no longer substitutes a random maze for an
  unknown name. It records the failure and `load_settings()` returns `0`, so
  the run fails rather than silently building a random world. All frozen
  scenarios name listed mazes (`Quadrant`/`Arena`), so G is unchanged; the
  explicit loader is the supported way to supply an unlisted maze.

### Display-free loaders and progress UI (`Src/file.c`)

`load_desc_lists()` retains its progress messages for the X front-end but the
`draw_text_rc()`/`sync_output()` calls are compiled out under `NULL_BACKEND`,
so the server's list loading is independent of the X progress UI. The explicit
single-asset loaders draw nothing at all.

### Score/results versus graphical stats wait (`Src/game.c`, `Src/setup.c`)

`display_game_stats()` mixed score reporting/reset with the interactive
`get_events()`/`win_exposed()` wait. The non-graphical part is factored into
`game_finalize_scores()` (plain score output + per-match score reset) and
exposed as `game_results()`, which returns the legacy auto-exit decision with
no event loop. `play_game()` now calls `game_results()` when
`server_presentation_active()` is false and keeps `display_game_stats()` for
the X front-end. The legacy tail behaviour is identical for the X path.

### Approved release configuration (`Src/init.c`, `Src/Include/server.h`)

- `server_release_settings()` starts from `init_settings()` and applies only
  the approved overrides: Combat, free-for-all (`team_score` off), respawn
  (`restart` on), bots may win (`robots_dont_win` off), individual winning
  score 1000, 15 Hz. Every other field keeps its `init_settings()` default.
- `server_config_release()` sets `tick_hz = 15` and
  `max_vehicles = SERVER_RELEASE_MAX_VEHICLES` (4), a new `ServerConfig`
  field. The approved special preset is `special_apply_mvp_preset()` (P1.11),
  which the release server applies (still gated by `XTANK_MVP_PRESET` in this
  checkout; P1.15 wires it unconditionally).

## `Tests/phase1/content.sh` (new)

Builds the display-free null candidate and:

1. Verifies each pinned asset's SHA-256 against the new
   `Tests/phase1/content.golden.sha256` (`pin 14e6d42…`).
2. Runs the shipped binary's test-only content self-check
   (`XTANK_CONTENT_CHECK`) with `DISPLAY`, `XTANK_DIR`, `HOME` and every other
   asset variable unset, against three roots:
   - the shipped asset tree → all three assets load and report `CONTENT-OK`;
   - a **listless** copy (no `Mazes/list`, no `Vehicles/list`) → `combat1`,
     `Arena` and `Vanguard` still load, proving list independence;
   - an empty root → nonzero exit with a `CONTENT-ERROR` reason.
3. Parses the self-check's settings dump and asserts the release config:
   Combat (`si_game=0`), FFA (`si_team_score=0`), respawn (`si_restart=1`),
   bots may win (`robots_dont_win=0`), `si_winning_score=1000`,
   `game_speed=15`, `max_vehicles=4`, `tick_hz=15`.
4. Diffs the release settings against a fresh `init_settings()` dump and
   requires the difference set to be exactly
   `{robots_dont_win, si_team_score, si_winning_score}` — i.e. every other
   default is preserved.
5. Checks the 12-entry approved preset: Console/Mapper/Radar/HUD permitted,
   New Radar/Tac Link/Camo/Rdf forced off.

The self-check lives behind a test-only `XTANK_CONTENT_CHECK` seam in
`get_environment()` (the repository's established `XTANK_GEOMETRY_*`/
`XTANK_SPECIALS_*` convention); a normal front-end or server run never sets
it. Deleting the seam later would not affect the production loaders.
