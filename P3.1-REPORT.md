### 6.3 `make phase2-check PHASE2_WITH_PHASE1=1` — PASS (invocation caveat)

The literal documented command fails in this environment for a **pre-existing
harness reason unrelated to the baseline**: run through `make`, the inherited
`make phase1-check` is a sub-make, which auto-enables `-w`; the resulting
`make[2]: Entering directory …` lines are then mis-parsed by
`Tests/phase1/check-x-boundary.sh --build` as server source names
(`p3.1/phase2-check.log`). This is an invocation/nesting artifact, not a
simulation difference, and is present on the unchanged P2.16 harness.

The same integrated gate passes with the non-invasive make flag that disables
directory banners (and, equivalently, by running the driver directly):

```
make --no-print-directory phase2-check PHASE2_WITH_PHASE1=1 \
     PHASE2_EVIDENCE=/tmp/opencode/xtank-phase3/p3.1/phase2-integrated
→ P1.16 PHASE1-CHECK PASS
→ P2.16 PHASE2-CHECK PASS (13 drivers + packages)   exit 0
```

Log: `p3.1/phase2-integrated.log`
(SHA-256 `29cc6de7521e7e80bb7ff175205b84a39dd55275460e08813f628bda98f568e7`).

Harness was left read-only; the caveat is recorded in `Tests/phase3/README.md`.
