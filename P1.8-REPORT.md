## Seed policy

- **Configured seed wins.** `main()` calls `server_config_seed_env()` before
  `server_init()`. When `XTANK_SEED` is present it is parsed strictly into
  `ServerConfig.seed` with `seed_set = 1`; `server_init()` then calls
  `server_seed_random(seed)` → `init_random_seed(seed)` → `SEEDRANDOM((int)seed)`
  before any `rnd()`/`rnd_interval()` call. `seed_set` is explicit, so a
  configured seed of `0` is honoured instead of being confused with "unset".
- **Absent seed, normal run.** With no `XTANK_SEED` and no replay output,
  `server_init()` keeps the pin's `init_random()` (`time()`-based), and the
  captured value is retained for the lifecycle oracle. Front-end behaviour is
  unchanged.
- **Absent/malformed seed, replay mode.** Replay mode is the `STATE_DUMP`
  oracle with `XTANK_DUMP` or `XTANK_TRACE` set. There a missing seed is fatal
  (`exit 2`, `"replay mode requires an explicit seed ..."`) and a malformed one
  is rejected at parse time (`rorre` → `exit 17`,
  `"Malformed XTANK_SEED; expected a decimal integer."`). Empty, non-numeric,
  trailing-junk and out-of-range values all fail the same way; there is no
  silent fall back to `time()` while producing a comparable dump.
- **Reset policy.** `server_match_seed()` makes the match-reset seed policy
  explicit: the production single-match path continues the initial stream (the
  pin's behaviour, so no frozen value changes); only the lifecycle replay oracle
  restarts each epoch from the captured configured seed so epochs stay
  self-comparable.
- **Shim stays reference-only.** `fixseed.so` is still preloaded for the frozen
  X reference (and for the pinned `--stage before` baseline, which predates the
  config seed). The `--stage after` candidate is run with `LD_PRELOAD` unset and
  takes `XTANK_SEED` from config.
