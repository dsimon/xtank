## Null backend design (`Src/Display/null.c`)

`null.c` is a genuine `GraphicsBackend`: it opens no display, allocates no
window-system resources, draws nothing, and synthesises neutral input. It
contains no `<X11/...>` include and no Xlib type or call. It defines the
opaque `struct video` with neutral bookkeeping only and implements:

- the `GraphicsBackend` vtable (`null_*` drawing/text/beep/flush/sync no-ops;
  `null_win_flags`/`null_expose_win`/`null_mapped` from the neutral window
  flags; `null_color_display` = `planes > 1`; fixed font metrics), installed
  as `graphics_backend = &null_backend`;
- the presentation entry points the UI still calls: `open_graphics`/
  `close_graphics`/`reset_video`/`set_video`, `make_video`, window
  make/map/unmap/clear, `get_events` (returns no events but keeps `ANIM_WIN`
  exposed so `map_windows()` terminates, mirroring the reviewed scratch
  behavior), `follow_mouse`/`button_up`, `multi_sync`, `set_cursor`,
  `make_picture`/`free_picture`, the X-free `rotate_pic_90`/`rotate_pic_180`
  byte rotations, `should_disp_name`, `get_default`/`get_num_default`, and the
  preference/state accessors (`video_*`) and the `vid`/`oldvid`/`team_color*`/
  `video_error_str` globals that callers reference.

Simulation-visible parity comes from reproducing the X backend's neutral side
effects (window expose/mapped flags, Video preference defaults, picture
bookkeeping); drawing itself is a no-op. No Xlib function under its own name is
provided. The header gate `GRAPHICS_POINTER_INPUT_ALWAYS_ON` is now also set by
`NULL_BACKEND`, matching the previously-proven input model.

### Named terminals for the v2 oracle (test hook)

The v2 bot-free traces bind named human slots (`playerA`/`playerB`) which the X
front-end obtains from the X resource database. A display-free backend has no
such database, so `make_video()` consumes a colon-separated list from
`XTANK_NULL_PLAYERS` (in terminal order); when unset the name stays empty and
v1 behavior is unchanged. `regression.sh` supplies the fixture names for the
null v2 runs and passes two terminal arguments so both slots exist. This is a
harness/test hook to be replaced by the explicit server config/intent path in
P1.7/P1.14/P1.15.

## `check-x-boundary.sh --build`

New mode: it asks the build for the explicit server list
(`make -C Src -s print-server-srcs`, with a fallback list), then for every
server TU generates a compiler dependency listing (`gcc -M`, system headers
included) with the exact server flags (no `-DX11`, `-DNULL_BACKEND`) and fails
if any dependency is an `<X11/...>` header or the backend-private
`Include/x11.h`. Dependency files are written to a private temp directory so
the build's own `nobj/*.d` are never clobbered. Result: **PASS (63 server TUs
X-free)**.

Calibration: the same dependency scan on `Display/graphics.c` compiled with
`-DX11` reports 8 X-header dependencies (X11/…, x11.h), confirming the check
would catch a leak.
