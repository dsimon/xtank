## Fixture defect log (S2)

1. Network leg passed constant `t=1000` to `server_session_step` while
   `server_session_service` used the advancing ns clock, so `t - last_rx_ms`
   underflowed and both peers were spuriously timed out (crash/early end).
   Fixed to `ns / 1000000ULL`, matching the shipped loop's single `now_ms()`.
2. The release traces have a gap (tick 1 then 60).  The real client refreshes
   liveness at 15 Hz; the fixture now emits `XTK_OP_HEARTBEAT` on idle ticks
   (accepted liveness, no engine effect).
3. `push_direct` zeroed the intent and never copied the trace operands, so
   every direct drive/turn/aim became 0.  Now copies `c->a`/`c->b`.
4. `firehold` stores on/off in the trace's 4th field (`c->a`), but `intent_op`
   read the empty 5th-field string.  Now uses `*a` when no token is present.
5. Epoch reset: network leg now has the admin client send `XTK_MSG_RESET`
   (returns from RESULTS or aborts from RUNNING) and waits for both clients to
   return to the lobby before re-ready/start.

Result: `direct.e{0,1} == network.e{0,1}` byte-identical at 200 ticks, Arena.

## Fixture defect log (S3)

6. Terminal-tick score reset.  The shipped `server_session_step` finalizes a
   finished match inside the call (`server_session_finish` -> `game_results`
   -> `game_finalize_scores`), which zeroes each combatant's per-match score
   *after* the tick snapshots/events are exported.  The frozen X reference
   dumps its authoritative end-of-tick state at the `game_rules` seam, before
   that post-match zeroing.  Reading the globals after `server_session_step`
   therefore differed from X only on the winning tick (`score 1000` vs `0`;
   kills/deaths and all other fields identical).  Fix: on a non-RUNNING tick,
   `parity_fixture.c` restores the captured pre-reset score from the immutable
   results (`server_events_results`, copied before the reset) before dumping.
   Read-only harness read-timing fix; no simulation state, tick, or gameplay
   rule changed.  After it, Arena natural win: X == direct == network on both
   epochs, byte-identical (`cmp`).

## Harness defect log (S4)

7. `parity.sh` passed the lowercase maze name `arena` to the fixture for the
   first scenario, but the maze file is `Mazes/Arena.m` and `make_mdesc` is
   case-sensitive, so the direct/network legs failed with "cannot load arena".
   Fixed the no-argument scenario list to pass `Arena`.
8. The `*-2000` traces do not reach a natural win (both tanks trade one kill
   each, score 1000, winning score 2000, and neither lands a second).  `run_x`
   had no tick bound, so the frozen reference ran unbounded (2.6M ticks, a
   7.2 GB dump) and hit the 600 s timeout.  Added a finite replay bound
   (`XTANK_P3_TICKS`, default 4000) applied to *both* legs: `run_x` now sets
   `XTANK_TICK_LIMIT` and the fixture receives `XTANK_P3_TICKS`.  Natural-win
   scenarios end earlier (arena 231, combat1 102) and are unaffected.  All four
   scenarios then pass.
