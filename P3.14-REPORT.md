## 2. S0 — impairment capability (real UDP, not in-memory)

Kernel `netem`/`tbf`/`red`/`choke` are **not available**: no `/lib/modules`,
`modprobe sch_netem` fails, `/proc/kallsyms` has no `netem` symbol, and
`tc qdisc add dev lo root netem delay 50ms` returns
`Error: Specified qdisc kind is unknown.` (verbatim in
`P3.14-CHECKPOINT.md` §S0 and `~/workspace/coding/xtank-evidence/p3.14/s0/`).

Impairment is therefore applied by `Tests/phase3/impairment_relay.c`, a
**userspace middlebox that forwards real loopback UDP datagrams** between the
shipped ENet server and two shipped client sessions.  It is *not* an in-memory
transport: the relay is a separate process, the server and clients use their
real ENet sockets, and every datagram is delayed/dropped/reordered at the UDP
layer.  A C probe measured symmetric 25 ms each way -> **~50 ms measured RTT**,
which is why the combined profile configures 25 ms (not 50 ms) per direction.
Missing real impairment would be BLOCKED; it was found and used.  **S0 PASS.**
