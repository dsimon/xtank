## Goal

Add an optional listen mode that preserves the Phase 1 local CLI and drives one
connected peer through the frozen protocol-v1 state machine
`Disconnected → Handshake → Lobby → Running → Results → Lobby`, with
allowlisted content, ready/start/reset administration (first/only peer is
admin), one peer + one drone, epoch barriers, and the D2-F two-second solo
timeout abort (neutral drive/fire, abort — never a scored death — cleanup and
return to lobby). The session is the glue that makes P2.6's events/results and
P2.7's admission part of the shipped server.

## Session flow

- **Handshake:** `HELLO` proto-version or content-digest mismatch → `REJECT`
  (`VERSION_MISMATCH` / `CONTENT_MISMATCH`), state → Disconnected, no catalog and
  no match; no auto-download. A valid `HELLO` → `WELCOME` + `CONTENT_CATALOG`.
- **Lobby:** `CONFIG_SELECT` validated against the allowlist
  (`combat1`/`Arena`, `Vanguard`) → `CONFIG_STATUS`; unknown IDs are refused with
  `BAD_CONTENT_ID` and no state effect. `READY` marks the (admin) peer ready.
  Input outside Running is `BAD_STATE`.
- **Running:** admin `START`/`RESET` builds/loads the allowlisted content, one
  human (slot 0) + one drone, resets `server_events` at `EPOCH_BEGIN`, binds the
  peer through P2.7's `server_net_session_bind()`/`begin_epoch()`, and emits
  `START`+`EPOCH_BEGIN`. Each tick admits inputs (P2.7 `server_net_admit_message`),
  runs `server_events_observe()` after `server_step()`, delivers the authorized
  keyframe-then-`VIEW_SNAPSHOT` on channel 1 and `EVENT`/`CMD_ACK`/`RESULTS`
  reliably on channel 0.
- **Results → Lobby:** a completed match (win) and a timeout/abort are distinct
  (`result_kind` 0 vs 1); RESULTS are captured before the score reset and
  retained until the admin `RESET`. `RESET` is accepted in Running and Results,
  tears down the live epoch first, and starts `prior_epoch+1`; only the admin may
  reset, a stale `prior_epoch` is refused. QUIT drops the session; a second peer
  is rejected `SESSION_FULL`.

### Fixes made during execution

The session module, fixture and script were present from an earlier partial
attempt but did not build or pass. Four defects were corrected:

1. `session_fixture.c` did not include `Protocol/content-manifest.h` (build
   failure); added the include.
2. `handle_reset` called `server_session_begin()` while RUNNING, which the begin
   guard rejected — so a mid-match admin reset did nothing. RESET now cleans up
   the live epoch (`server_session_return_to_lobby`) before starting the next.
3. `server_session_run()`'s `SERVER-LISTEN` line was block-buffered when stdout
   was redirected, so the display-free listener check saw an empty log; added
   `fflush(stdout)`.
4. The network fixture consumed the transport CONNECT event before
   `server_session_service()` could accept the peer (no session), and assumed
   `CONFIG_STATUS` was the next client message ahead of a queued catalog. The
   fixture now drives the production service path and drains to `CONFIG_STATUS`.

## Constraints honored

- **D2-F provisional abort** implemented exactly: one peer, first peer
  administers start/reset; two seconds without valid traffic → neutral
  drive/fire, `GAME_OVER` abort result (never a death, no score, no pending
  respawn), cleanup, return to lobby. Not redesigned.
- **Allowlisted content, no auto-download:** `combat1`, `Arena`, `Vanguard` only;
  a digest/ID mismatch fails before start.
- **P2.6/P2.7 wiring:** `server_events_reset(epoch, first_tick)` at
  `EPOCH_BEGIN`; `server_events_observe()` after every `server_step()`;
  `server_events_results()` delivered reliably on channel 0 before/after the
  score reset; admission goes through `server_net_*` with the P2.7 pre/post-step
  bookkeeping (`server_net_post_step(frame)`). The engine is touched only on the
  simulation thread.
- **No mid-match join/resume, no admin transfer, no new gameplay defaults;**
  ordinary completed matches (`result_kind` 0) and aborted sessions
  (`result_kind` 1) are distinct.
- Dumps, logs, binaries and reference worktrees stay outside the checkout;
  `netobj/` and `xtank-server-net` are ignored.
