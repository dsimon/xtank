offsets, channels, sizes, state transitions and version rejection, and land the
portable codec that implements them — without unapproved schema or knowledge

## 3. What was frozen (approved only)

The approved §5 rows, implemented exactly:

- **Exact version 1.1 (D3-A):** `version_major=1`, `version_minor=1`; a 1.0
  envelope is rejected `XTK_ERR_VERSION_MISMATCH` with no fallback; a non-1
  major is `XTK_ERR_BAD_VERSION`. No dual-version stack.
- **LOBBY_STATE (0x19, ch0, reliable, D3-C):** config revision, session state,
  maze/vehicle u16 IDs, drone count, self/admin index, bounded human roster
  (≤2) with stable connection/controller identity, slot, readiness, departure
  flags/reason and names. Valid in lobby/results/running. No hidden
  vehicle/HUD/score data.
- **START_REQUEST (0x1A, ch0, admin-only, D3-B):** expected config revision;
  rejected `NOT_ADMIN`/`NOT_READY`/`STALE_CONFIG`.
- **Config/ready extension (D3-B):** CONFIG_SELECT/CONFIG_STATUS carry
  `drone_count`; CONFIG_STATUS carries `config_revision`; READY is an explicit
  `ready`/`unready` toggle against a revision; START carries full-width
  `vehicle_id` + `drone_count` + revision; WELCOME advertises `human_capacity`.
- **Input life stamp (D3-C):** COMMAND carries a u32 `life_generation` in both
  INPUT_BATCH and RELIABLE_CMD; ACK can report `XTK_ERR_STALE_LIFE`.
- **Full entity lifetime keys (D3-C):** u32 generations for snapshot header/
  SelfState/VehicleView/Results entries and bullet/explosion own generation;
  u32 bullet owner generation; landmark full-width id + full grid key. Positions
  and operands remain binary64.
- **Reliable initial-view barrier (D3-C):** `VIEW_KEYFRAME` (0x30, ch0) with the
  identical snapshot layout, `KEYFRAME` set.
- **Occurrence-ticked, recipient-scoped events (D3-C):** EVENT gains
  `capture_tick`; `event_sequence` is recipient-local; departure is conveyed by
  session status + snapshot disappearance, no REMOVE event; `map_revision`
  remains recipient-local.
- **Departure marker (D3-D):** RESULTS entries carry `XTK_FLAG_DEPARTED`.
- **Fairness/identity/timeout (D3-E):** `XTK_ERR_DUPLICATE_NAME`,
  `XTK_HANDSHAKE_TIMEOUT_MS`; unchanged global service/intent bounds.
- **No reserved-field reuse:** every v1.0 reserved field remains reserved=0 and
  is now *enforced* on decode; all new data was appended as new bytes.

**Explicitly not done** (stop-condition guards): no new gameplay op, no changed
op range, no VIEW-v1 knowledge widening, no compression/delta/quantization, no
REMOVE event, no reserved reinterpretation, no dual-version path, no content/
asset/geometry/preset/manifest change.

## 4. Byte-level correctness of the codec

- `Tests/phase3/fixtures/protocol/verify.py` is an **independent** decoder
  written from the `docs/PROTOCOL-v1.1.md` offsets; it does not import the
  generator and does not call the C codec. It verifies 24 fixtures / 261 checks.
- `Tests/phase3/codec_fixture.c` builds each message from hand-authored values,
  encodes and compares to the committed golden bytes, decodes the golden and
  re-encodes to byte identity, and asserts the emitted version is 1.1.
- Worst-case `VIEW_*` payload is **33 872** bytes (message 33 904), below
  `XTK_MAX_MESSAGE_BYTES` (65 536); `sizeof(XtkMessage)` is 39 432 bytes.
- `nm` shows no `malloc/calloc/realloc/free/aligned_alloc/posix_memalign` in
  `encode.o`/`decode.o`; no native struct is copied.

## 5. Rejection coverage (251 checks)

For every fixture: raw truncation at every prefix, and truncation with a
matching declared `payload_length` at every interior offset. Plus explicit
cases:

- **Version:** 1.0 ⇒ `VERSION_MISMATCH` (no fallback); 1.2 ⇒ `VERSION_MISMATCH`;
  2.1 ⇒ `BAD_VERSION`.
- **Envelope:** bad magic, unknown type, wrong channel (LOBBY_STATE on ch1,
  VIEW_KEYFRAME on ch1), nonzero envelope reserved, negative tick,
  `payload_length` wrap, inconsistent length, trailing octet.
- **Counts:** oversized INPUT_BATCH/RELIABLE_CMD/CMD_ACK/CATALOG/RESULTS/
  VIEW_SNAPSHOT/LOBBY_STATE counts and HELLO/roster name lengths.
- **Reserved (every new field):** WELCOME, CONFIG_SELECT (1/2/4), CONFIG_STATUS
  (1/2), READY (1/2), START (1/2), START_REQUEST, LOBBY_STATE (1/2), RESULTS
  header + entry, RESET, CMD_ACK, PROTOCOL_ERROR, RELIABLE_CMD + COMMAND,
  INPUT_BATCH + COMMAND, and every snapshot section (header, SelfState ×2,
  VehicleView ×2, BulletView, ExplosionView, LandmarkView ×3, RadarBlip) —
  each yields `XTK_ERR_MALFORMED`.
- **Strings:** non-ASCII HELLO and roster name bytes ⇒ `MALFORMED`.
- **Non-finite:** NaN and +Inf `f64` operands ⇒ `NONFINITE`; encoder rejects
  NaN, oversized counts and unknown types.

## 7. Build integration notes (honest debt, not claimed green)

P3.3 is the codec-freeze checkpoint that precedes session integration (P3.4+).
The following are **expected** and are recorded rather than hidden:

- The Phase 2 **network/session drivers** (`Tests/phase2/codec.sh`,
  `session.sh`, `input.sh`, `view.sh`, …) exercise v1.0 messages against the
  codec and are **superseded** by the v1.1 schema until P3.4 wires the session;
  they are not re-run or claimed as passing in this task. v1.0 fixtures
  themselves remain verified by the independent verifier.
- `Src/server_session.c:727` still narrows `vehicle_id` to `u8`; the codec now
  exposes full-width `u16`. Fixing the server call site is P3.4 work. The file
  still compiles against v1.1 (`gcc -fsyntax-only` passed).
- `Client/menu.h` already defined a client type named `XtkLobbyState`; the new
  wire message struct was therefore named **`XtkLobbyStatus`** (message id
  `XTK_MSG_LOBBY_STATE`) to avoid a namespace collision. The Client's
  `frame.c`/`menu.c`/`input.c` syntax-check against the new `Protocol/` headers.
