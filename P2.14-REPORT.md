## Goal

The live client frame loop that wires the P2.8 session protocol, the P2.11
snapshot model/camera/one-tick interpolation, the P2.12 input controller and the
P2.10/P2.13 renderer + HUD/map/radar/menu into one nonblocking playable slice:

```
connect -> handshake -> lobby -> ready -> start -> 60 ticks of play with input
  -> results -> reset -> clean disconnect
```

The loop never blocks, never schedules a simulation tick and runs no client
simulation; the server remains the sole owner of movement, collisions, damage,
RNG, bots and scoring. Presentation speed cannot advance the world.

## Boundary and constraints honored

- **No simulation on the client.** `frame.o`/`session_client.o` have no
  SDL/ENet/simulation undefined symbol (`nm` check); `session_client.{c,h}` and
  `frame.{c,h}` include no SDL/X11/ENet/engine header and reference no
  `play_map`/`intent_push`/`real_map`. The fixture links the simulation only to
  *host* the authoritative server, as a test harness.
- **Never blocks.** The frame loop only calls `transport_service` (zero timeout,
  bounded budget), pure compute and surface drawing; DNS/connect happens once in
  `session_client_connect()`.
- **Presentation never schedules ticks.** Input is emitted from observed server
  ticks (with a bounded wall-time heartbeat fallback); rendering uses the model's
  monotonic estimated server time minus the one-tick buffer (D2-E).
- **Server authority / ownership.** The client never supplies its own player
  slot; the session maps connection→slot on the server (P2.7/P2.8). Input ops are
  the release-authorized subset only.
- **X boundary.** No `Src/` file touched; `make phase1-check` passes all modes.
