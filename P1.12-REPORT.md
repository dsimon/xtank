## Boundary and bookkeeping design

### Presentation-pass gate

`Src/server_core.c` gains `server_presentation_active()` — distinct from the
P1.11 specials draw gate. It is `1` for the X front-end and natively `0` for
the `NULL_BACKEND` server (`XTANK_SERVER_PRESENT` is a test-only control). In
`animate()` the per-terminal input poll, the display pass and the
synchronization point are all gated on this predicate. `Src/setup.c` likewise
skips its `sync_terminals(TRUE)` flush under `NULL_BACKEND`.

### Reproduced side effects (exact legacy phase)

When the terminal pass does not run, `animate()` still performs the
simulation-visible side effects it had, at the same phase — after the tick's
`state_dump`/`game_rules` and the pre-bookkeeping early return, and before the
sync point:

- **Last-terminal disc clearing** — `disc_clear_throwers()` (`Src/disc.c`)
  resets each `DISC` bullet's transient `thrower` colour exactly as the last
  terminal's `display_bullets()` did. `display_bullets()` now calls the same
  function (`if (lastterm) disc_clear_throwers();`) so both paths share one
  copy of the rule. This is the field that participates in the v1 checksum, so
  the reset must happen at the same tick phase (never earlier than the dump).
- **Camouflage shadow advancement** — `camo_advance_shadows()` (`Src/camo.c`)
  performs the legacy `old_camod = camod` sweep over all `MAX_VEHICLES` slots,
  live or not.
- **Map-window knowledge commit** — `display_map_commit()` (`Src/display.c`)
  reproduces the part of `display_map()` that is simulation-visible (notably
  New Radar's `need_redisplay` flag, cleared via `nr_t_redisplay`, and the
  drawn-blip bookkeeping that feeds the next update). It consumes the map
  window's expose state exactly as `check_expose()` did (so the first exposed
  frame commits with `SP_draw` and later frames with `SP_redisplay`, matching
  the reference transition), and invokes the map specials' proc directly so the
  commit is independent of whether a terminal is presenting. The null backend
  paints nothing.

The inert fields are deliberately untouched: `Loc.screen_x/screen_y`
(`loc.h`), `Vehicle.old_camod` (`vehicle.h`) and `Bullet.thrower` (`bullet.h`)
are unchanged.

## `check-x-boundary.sh --runtime`

The new mode builds the display-free (`null`) candidate, compiles a small
link-time instrumentation shim and relinks the server objects with
`-Wl,--wrap=` around `display_terminal`, `update_screen_locs`,
`sync_terminals`, `get_events` and `multi_sync`. Counters are bumped only while
`server_step()` is on the stack, so terminal construction at startup cannot
inflate the tick-path counts. It then:

1. runs a whole `combat-2drone` match (seed 114336) with presentation off and
   requires every counter to be zero while the tick count is positive;
2. requires the produced v1 dump to be byte-identical to the frozen reference
   (`76f23a33…88c6a`, 798 lines);
3. runs a forced-presentation control (`XTANK_SERVER_PRESENT=1`) and requires
   the counters to fire, proving the instrumentation is live.

```
RUNTIME ticks=26569 display_terminal=0 update_screen_locs=0 sync_terminals=0 get_events=0 multi_sync=0
RUNTIME ticks=50 display_terminal=49 update_screen_locs=49 sync_terminals=49 get_events=50 multi_sync=49   (control)

check-x-boundary: PASS (server made 0 render/event/sync calls over 26569 ticks;
                    dump sha 76f23a…88c6a == frozen; control display_terminal=49)
```

## Deferred / notes

- The server still constructs one inert `Terminal` through `main()`'s
  `displayname` fallback, so `check-x-boundary.sh --runtime` proves "no
  terminal render/event/sync call" rather than literally zero `Terminal`
  structs. A genuinely terminal-free entry lands with the P1.15 server main
  and reuses this same bookkeeping. With the null backend the terminal presents
  nothing, so the simulation advances with no terminal pass.
- `display_map_commit()` calls the map specials' callbacks directly, bypassing
  the P1.11 draw gate; on the null backend those callbacks' draw primitives are
  no-ops and are not counted by the runtime instrumentation. The check's
  contract is the terminal render/event/sync entry points the server no longer
  reaches.
- `Tests/phase1/specials.sh` still passes, but its `draw`/`suppressed` counter
  magnitudes are smaller than before because the server no longer dispatches
  the per-tick map draws through `do_special`; the knowledge records
  (`mapper`/`radar` counts) are unchanged.
- `Src/newradar.c` was modified during development to expose a targeted commit
  and then fully reverted in favour of the more faithful `display_map_commit()`
  in `display.c`; it carries no net change.
- `timing.sh` and the 60-minute bot scenarios were not re-run for this task
  (pacing and bot scheduling are untouched); they remain P1.9/P1.13 evidence.
