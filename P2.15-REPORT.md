## Goal

Prove the real network path does not change a game outcome: drive one match and
one deterministic, release-authorized command log three ways and require the
authoritative per-tick state and the decoded client view to match exactly.

```
leg X        frozen pinned X reference, legacy controls (reference_input.c trace)
leg direct   shipped terminal-free server core + P2.8 session, intents pushed
             straight into the bounded queue (no transport)
leg network  the same core/session, commands encoded by the P2.3 codec, carried
             over the pinned P2.7 ENet transport to a real P2.14 client session;
             P2.7 admits, P2.8 steps, and the P2.11 client model consumes the
             authorized VIEW_SNAPSHOT stream
```

## Why this is a valid three-way comparison

The scenario is expressed with **release-authorized ops only** (`drive`,
`driveabs`, `turn`, `aim` world, `fire`, `firehold`, `wep`) so the identical
command log is executable by the legacy controls (reference_input.c), the intent
queue (both directly and as the codec/admission maps them) and the network
client. The frozen `trace-arena`/`trace-quadrant` traces use `chase`/`standoff`
(test-only, rejected on the wire) and could not be replayed over ENet, so this
audit uses its own schedule on Arena — one of the two allowlisted release mazes
and one of the `Mazes/list` names the legacy settings parser can resolve.

`leg X` and `leg direct-intent` use the legacy settings path
(`Tests/phase1/build-reference.sh`); `leg direct`/`leg network` use the shipped
P2.4/P2.8 match build (`server_players` binding + `build_combatants`). The two
produce the same combatant flags: human `num_players == 1`/`teleport == TRUE`,
drone `num_players == 0`/`teleport == FALSE` (P2.4).

### One configuration divergence found and reported (not masked)

The legacy settings parser reads the team from the `V#` line; the shipped
`build_combatants()` assigns the drone `2 % MAX_TEAMS` (Orange) and the human
`1` (Red). With the scenario's first draft (`Blue` for the drone) the X leg
differed from the network leg at the first `V 1` record — `team 5` vs
`team 2` — which then cascaded through team bookkeeping and the autonomous
drone. This is a **match-construction** difference, not a transport effect. Per
PHASE2-PLAN §5.B ("match initial placements") the scenario's drone team was set
to `Orange` so the legs start from identical placements; no gameplay code was
changed to achieve parity. Recorded here rather than silently blessed.
